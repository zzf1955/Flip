## 2. G1 身体构型

G1 有两种身体构型（23DOF / 29DOF），差异在腰部和手臂：

| 部位 | 23DOF (Basic) | 29DOF (EDU Plus+) |
|------|---------------|-------------------|
| 腿 | 6 x 2 = 12 | 6 x 2 = 12 |
| 腰 | **1** DOF (仅 yaw) | **3** DOF (yaw+roll+pitch) |
| 臂 | **5** x 2 = 10 (无腕) | **7** x 2 = 14 (含腕 roll/pitch) |

## 3. G1 手部选配

| 手型 | 厂商 | 手指 | DOF/手 | 加身体后总 DOF | 特点 |
|------|------|------|--------|---------------|------|
| **Rubber Hand** | 宇树 | 一体式 | 0 (fixed) | 29 | 不可动橡胶手，EDU Plus 默认配置 |
| **Unitree Dex3** | 宇树自研 | 3指 | 7 | 43 | 力控三指，适合工业抓取 |
| **Inspire RH56 FTP** | Inspire Robots | 5指 | 6 (12关节) | 41 | 仿人五指，适合遥操作 |
| **BrainCo Revo2** | 强脑科技 | 5指 | 6 (11关节) | ~41 | 轻量五指，内置 RGB 摄像头 |

### EDU Plus 手部确认

通过 URDF 数据确认，`g1_29dof_rev_1_0.urdf` 中 EDU Plus 自带 **rubber_hand（橡胶手）**：

```
left_hand_palm_joint (fixed) → left_rubber_hand   # meshes/left_rubber_hand.STL
right_hand_palm_joint (fixed) → right_rubber_hand  # meshes/right_rubber_hand.STL
```

不是"没有手"，而是一体式不可动手掌。

## 5. URDF 初始姿态分析

### 关节 origin rpy 偏移

URDF 中多个关节的 origin 有非零 rpy，这是 STL 导出的参考构型补偿：

| 关节 | rpy 偏移 | 含义 |
|------|----------|------|
| left/right_hip_roll_joint | pitch -0.1749 rad (-10.0°) | 大腿微弯 |
| left/right_knee_joint | pitch +0.1749 rad (+10.0°) | 膝盖反向补偿 |
| left_shoulder_pitch_joint | roll +0.2793 rad (+16°) | 手臂自然外展 |
| right_shoulder_pitch_joint | roll -0.2793 rad (-16°) | 手臂自然外展 |

### 左右对称性

所有关节偏移完全左右对称，URDF 零位**不会**导致机器人向左或向右歪。
如果渲染出歪，原因来自数据集中 freeflyer 四元数 `rq[3:7]` 反映的实际机器人朝向。

### 代码处理

`video_inpaint.py` 中的 `build_q` + `do_fk` 正确处理：
- Pinocchio FK 引擎自动处理 joint origin rpy 偏移
- 四元数转换 `(w,x,y,z)` → Pinocchio `(x,y,z,w)` 正确

## 7. WBT 数据下载

Unitree `UnifoLM_WBT_Dataset` collection 中，当前项目默认下载 Brainco 手和两组
Inspire 手数据，排除额外的 Dex1 repo：

- `brainco`：Brainco 手，4 个 repo，Hub 总大小约 47.46 GB。
- `inspire_dex5`：Inspire 手，Hub repo 内带 `G1_WB_Dex5_*` 顶层目录，3 个
  repo，总大小约 11.10 GB。
- `inspire_flat`：Inspire 手，扁平 LeRobot layout，6 个 repo，总大小约
  107.47 GB。

三组合计约 166.03 GB（十进制 GB；约 154.63 GiB）。下载入口：

```bash
scripts/flip_run.sh unitree_wbt_download -- --dry-run
scripts/flip_run.sh unitree_wbt_download -- --background --workers 8
```

默认目标目录为 `data/unitree_G1_WBT/<repo_name>/`，日志写到
`training_data/log/unitree_wbt_download/<timestamp>/`。后台模式会立即返回 PID，
持续日志在该目录的 `download.log`。

脚本逐文件读取 Hugging Face 文件清单，已有且 size 匹配的文件会跳过；缺失文件先
下载到 Hugging Face hub cache（优先 `HF_HUB_CACHE`，否则 `$HF_HOME/hub`；通过
`flip_run.sh` 启动时默认是 `/disk_n/zzf/.cache/huggingface/hub`），再硬链接到目标
目录，跨文件系统时退回普通 copy。对 `inspire_dex5` 三个 repo，脚本会在落盘时剥掉
远端 `G1_WB_Dex5_*` 前缀，使本地结构保持为：

```text
data/unitree_G1_WBT/<repo_name>/
├── data/
├── meta/
├── videos/
├── .gitattributes
└── README.md
```

常用子集：

```bash
scripts/flip_run.sh unitree_wbt_download -- --groups brainco --background
scripts/flip_run.sh unitree_wbt_download -- --groups inspire_dex5,inspire_flat --background
scripts/flip_run.sh unitree_wbt_download -- --repo G1_WBT_Brainco_Pick_Up_Medicine --background
```

如果需要走 Hugging Face 镜像，可显式传入 endpoint：

```bash
scripts/flip_run.sh unitree_wbt_download -- --endpoint https://hf-mirror.com --background
```

## 8. WBT 外观域、可用时长与相机选择

WBT 数据的训练边界按机器人外观划分。Brainco 手是独立外观域；Inspire 手当前又按
`data/unitree_G1_WBT/Appearance.md` 拆成两种不同外观。`inspire_dex5` 与
`inspire_flat` 只是 Hugging Face 源仓库/采集 layout 分组，不能再当作训练外观分组。

| 外观域 | 数据来源 | 当前任务 |
|--------|----------|----------|
| `brainco` | 任务名以 `G1_WBT_Brainco_` 开头 | `Collect_Plates_Into_Dishwasher`、`Make_The_Bed`、`Pick_Up_Medicine`、`Pickup_Pillow` |
| `inspire_app1` | `Appearance.md` 中标记为 `1` | `Collect_Clothes_MainCamOnly`、`Pickup_Pillow_MainCamOnly`、`Put_Clothes_into_Washing_Machine`、`Put_Clothes_into_Washing_Machine_MainCamOnly` |
| `inspire_app2` | `Appearance.md` 中标记为 `2` | `Clean_The_Living_Room`、`Pick_Up_Drinks`、`Put_Clothes_Into_Basket`、`Put_Drinks_Into_Fridge`、`Put_Vegetables_Into_Basket` |

训练时必须保持这三个外观域隔离，不能把 Brainco、Inspire 外观 1、Inspire 外观 2 混到
同一个 appearance-learning 数据集、pair/cache duration 或 LoRA run 中。具体约束：

- `identity_r2r`、`blur_r2r`、`h2r` / `r2h` 的 pair layout 和 VAE/T5 cache 都应按
  `brainco`、`inspire_app1`、`inspire_app2` 分开生成。
- 三阶段 Wan/Mitty LoRA 应分成三条并行训练线。三条线可以共享 base model、训练代码、
  超参和调度方式，但 LoRA 权重、run name、duration label 和评估结果要分别记录。
- `Appearance.md` 是 Inspire 任务分组的本地事实来源；新增 Inspire 任务必须先写入该文件，
  再进入 pair/cache/训练数据生成。
- 跨外观比较应在独立 checkpoint 完成后做评估汇总，不应通过混合训练让一个 LoRA 同时
  记忆多种机器人外观。

建议 duration / run 命名显式带外观域，例如 `2s61f30_g1_wbt_brainco_v1`、
`2s61f30_g1_wbt_inspire_app1_v1`、`2s61f30_g1_wbt_inspire_app2_v1`，避免后续 cache
或 checkpoint 被误用。
