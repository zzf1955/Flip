## 背景

task076 已交付 `2s61f30` 视频 slice 和 pair layout：

- robot original：`training_data/slice/g1_2s61f30/original/`，10908 条。
- SAM2 blur：`training_data/slice/g1_2s61f30/sam2_blur/`，10908 条。
- Seedance：`training_data/slice/g1_2s61f30/seedance_direct/`，84 条。
- pair layout：`training_data/pair/{identity_r2r,blur_r2r,h2r}/2s61f30/`。

但 task076 的 Seedance 切片是 robot-driven：每条 4s Seedance source 只复用
robot 的 `clip00` 和 tail-aligned `clip01` 窗口，不是密集滑动窗口，也没有 flip
增强。现在需要为 Step1 增加 Seedance 2s 滑动窗口数据；由于切片窗口不同，
Step1 对应的 robot origin 也必须按同一滑动窗口重新生成或精确 hardlink，不能直接
把 task076 的 old origin 目录作为 Step1 origin 使用。

Step2 的 robot-only 数据已经满足需求：origin 和 SAM2 blur 均为三任务全量
`2s61f30` 数据，后续只需要按新的 step layout 配对/发布即可。

## 目标

- 新建 Seedance 2s 滑动窗口切片数据，并同步生成与每个 Seedance window 完全对齐的
  robot origin 切片。
- 将最终训练数据发布为清晰的 step layout，默认根目录为：

```text
training_data/g1_2s61f30_seedance_slide/
├── step2/
│   ├── origin/
│   └── blur/
└── step1/
    ├── origin/
    └── human/
```

- `step2/origin` 与 `step2/blur` 复用 task076 已验证的 robot original / SAM2 blur
  数据，优先 hardlink，不重复编码。
- `step1/human` 来自 Seedance 4s 源视频的 2s 滑动窗口切片。
- `step1/origin` 必须与 `step1/human` 一一对应，使用相同 `task/episode/seg`、
  `clip_start_frame`、`source_frame_indices` 和 `source_id` 语义。

## 范围

- 新增或扩展数据生成脚本；不能覆盖 task076 已生成的
  `training_data/slice/g1_2s61f30/` 和 `training_data/pair/*/2s61f30/`。
- 保持 `2s61f30` 口径：30fps、61 帧、Wan `4k+1` 输入长度。
- Seedance 滑动窗口 stride 必须参数化；默认建议使用 `0.5s` stride，以复用旧
  `seedance_clip.py` 的密集滑窗语义。对 4s/120 帧 robot segment，默认窗口起点应为
  `0, 15, 30, 45, 59`，其中 `59` 是 tail-aligned 起点。
- 每条 Step1 样本都要写 manifest，至少包含：
  `source_id`、`source_segment_id`、`task`、`episode`、`seg`、`clip_idx`、
  `clip_start_frame`、`source_frame_indices`、`human_source_frame_indices`、
  `tail_aligned`、`origin_video`、`human_video`、`seedance_source_video`。
- 每条 Step2 样本都要写 manifest，至少包含：
  `source_id`、`source_segment_id`、`task`、`episode`、`seg`、`clip_idx`、
  `clip_start_frame`、`source_frame_indices`、`origin_video`、`blur_video`、
  `sam2_mask_path`。
- 允许对 Step1 中与 task076 完全同源且 `source_frame_indices` 完全一致的窗口使用
  hardlink；但不能用旧 origin manifest 代替新的 Step1 manifest。
- 本任务只负责数据 slice / layout / manifest；不生成 T5/VAE cache，不启动训练。

## 实施计划（分步骤）

1. 复核 task076 输出与 Seedance 4s 源：
   - 读取 `training_data/slice/g1_2s61f30/{original,sam2_blur}/index.jsonl`。
   - 读取 `training_data/seedance_direct/4s/<task>/ep*/seg*_human.mp4`。
   - 确认每个 Seedance 4s 源能映射到对应 robot segment 和 SAM2 mask。
2. 定义新的输出根目录与 manifest schema：
   - 默认 `training_data/g1_2s61f30_seedance_slide/step2/{origin,blur}`。
   - 默认 `training_data/g1_2s61f30_seedance_slide/step1/{origin,human}`。
   - 每个 step 写 `index.jsonl`，每个 task 写 `manifest.jsonl`。
3. 生成 Step2 layout：
   - 从 task076 的 original / SAM2 blur slice 精确 hardlink 到 `step2/origin`
     和 `step2/blur`。
   - 复制或重写 manifest，确保路径字段指向新的 step layout。
   - 不重新 blur、不重新编码视频。
4. 生成 Step1 Seedance 滑动窗口 specs：
   - 对每个 Seedance 4s source，按 `window=61 frames @ 30fps`、
     `stride=0.5s` 默认策略生成窗口。
   - 使用 robot 30fps timeline 生成 `source_frame_indices`。
   - 使用时间戳映射生成 `human_source_frame_indices`，并记录 Seedance source fps。
5. 生成 Step1 视频：
   - `step1/human`：从 Seedance 4s mp4 按 `human_source_frame_indices` 取帧，
     输出 30fps / 61 帧视频。
   - `step1/origin`：从对应 robot segment mp4 按同一窗口的
     `source_frame_indices` 取帧，输出 30fps / 61 帧视频；如果与 task076 已有
     original clip 完全同源同帧，允许 hardlink。
6. 写出 Step1 / Step2 manifest 和 summary：
   - 统计每个 task 的样本数。
   - 显式记录 Step1 Seedance 滑窗起点分布。
   - 显式记录 Step2 来源为 task076 数据。
7. 更新文档：
   - `doc/step_5_training_infra.md` 说明新的 step layout 与 task076 的区别。
   - `doc/scripts_inventory.md` 记录新增或扩展的数据生成入口。
   - `doc/requirement-log.md` 记录交付状态。

## 验收标准

- 新目录存在且不覆盖 task076 产物：

```text
training_data/g1_2s61f30_seedance_slide/step2/origin/
training_data/g1_2s61f30_seedance_slide/step2/blur/
training_data/g1_2s61f30_seedance_slide/step1/origin/
training_data/g1_2s61f30_seedance_slide/step1/human/
```

- Step2 样本数应与 task076 robot-only 数据一致：`origin=10908`、`blur=10908`，
  除非实施时显式改动 task 范围。
- Step1 `origin` 与 `human` 数量必须相等，且每条 manifest 记录都能通过
  `source_id` 一一配对。
- Step1 的 `origin` 与 `human` 必须共享相同 `task/episode/seg/clip_start_frame`
  语义；manifest 中的 `source_frame_indices` 和 `human_source_frame_indices`
  都必须为 61 长度。
- 对至少一个 4s Seedance source，Step1 应体现滑动窗口数量多于 task076 的
  robot-driven `clip00/clip01` 两个窗口；默认 0.5s stride 下应包含约
  `0, 15, 30, 45, 59` 这类起点。
- 抽样视频应为 30fps、61 帧，分辨率与源数据一致。
- 缺少 Seedance 源、robot segment、SAM2 mask 或帧数不一致时直接失败；不做静默
  fallback 到旧数据。

- 正式生成后校验：

  - Step1 origin/human 一一配对。
  - Step2 origin/blur 一一配对。
  - hardlink 样本的 inode 可选抽查，确认未重复占用大量磁盘。
