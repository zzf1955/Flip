## 背景

当前 G1 blur 数据仍依赖 SAM2 / FK 相关 mask 产物：

- `src.pipeline.g1_2s_slice_data` 生成 `2s61f30` 数据时强制读取
  `training_data/sam2_mask/<task>/<episode>/<seg>.npz`，写出
  `training_data/slice/g1_2s61f30/sam2_blur/`，并在
  `blur_r2r/2s61f30` manifest 中记录 `control_degrade=sam2_blur`。
- `src.pipeline.make_pair` 的旧 1s `blur_r2r` 路径也硬编码读取
  `training_data/sam2_mask/`，再对清晰 robot clip 的 mask 区域做 Gaussian blur。
- 本地当前 G1 canonical 三任务为：
  - `Inspire_Collect_Clothes_MainCamOnly`：593 segments。
  - `Inspire_Pickup_Pillow_MainCamOnly`：964 segments。
  - `Inspire_Put_Clothes_into_Washing_Machine`：3897 segments。
  - 合计 5454 segments；`2s61f30` 每 segment 2 个 clip，因此
    `original/sam2_blur/blur_r2r` 当前均为 10908 条。
- 非 canonical 但本地也存在 segment / SAM2 mask 的 G1 task：
  - `Inspire_Put_Clothes_Into_Basket`：1755 segments。
  - `Inspire_Put_Clothes_into_Washing_Machine_MainCamOnly`：754 segments。

H2R 已有维护中的 SAM3/SAM3.1 流程：

- `src.pipeline.h2r_sam3_precompute` 使用 `sam3` conda 环境，对短 1s clip 调用
  SAM3.1 text-conditioned video segmentation，输出 episode 级 `.npz`，包含
  `masks`、`covered_frames`、prompt 和 clip 参数。
- `src.pipeline.h2r_sam3_blur_pair` 只消费预计算 SAM3 mask，不隐式调用 SAM3；
  缺少 mask 或 frame/mask 对齐不一致时直接失败。
- H2R 实测 SAM3.1 16 帧可跑，32/80 帧会 OOM。G1 `2s61f30` blur 需要 30fps
  每一帧 mask：每个 4s segment 的两个窗口 `0..60` 和 `59..119` 合并后覆盖
  全部 120 帧，因此 G1 不能把 61/120 帧一次性丢给 SAM3，应按短 chunk 预计算并
  严格校验 coverage。

用户希望把 G1 的 blur 也切换为 SAM3，减少当前 SAM2/FK 分割链路对 stage2 blur
数据的依赖。当前 active task078 仍以 SAM2 blur 作为 step2 口径；如果本任务先实施，
task078 的 step2 blur/cache 口径应同步改为 SAM3，避免继续生成旧 SAM2 cache。

## 目标

- 新增 G1 SAM3/SAM3.1 mask 预计算入口，输入
  `training_data/segment/<task>/<episode>/seg*_video.mp4`，输出可复用的 G1 SAM3
  mask artifact。
- 将 G1 blur_r2r 数据生成从 SAM2 mask 切换为 SAM3 mask：
  - 新的 blur slice / pair manifest 必须明确记录 `control_degrade=sam3_blur`。
  - manifest 必须记录 `sam3_mask_path`、SAM3 model/version、prompt、chunk 参数和
    `covered_frames` 校验结果。
- 保持“预计算 mask”和“生成 blur 数据”显式分离；blur 数据生成入口不能隐式运行 SAM3。
- 缺少 SAM3 mask、mask 不覆盖所需 source frame、frame/mask 尺寸不一致、prompt 输出为空
  超过阈值等情况必须直接失败；禁止静默 fallback 到 SAM2 或旧数据。
- 更新训练/评估/文档中对 G1 blur mask 的命名和路径说明，避免新 SAM3 数据继续被当作
  `sam2_mask` 消费。

## 范围

- 默认数据范围为 G1 canonical 三任务：

```text
Inspire_Collect_Clothes_MainCamOnly
Inspire_Pickup_Pillow_MainCamOnly
Inspire_Put_Clothes_into_Washing_Machine
```

- G1 SAM3 mask 默认输出为 segment 级 artifact，路径建议：

```text
training_data/g1_sam3_mask/<task>/<episode>/<seg>.npz
training_data/g1_sam3_mask/<task>/<episode>/<seg>.json
training_data/g1_sam3_mask/index.jsonl
```

- `.npz` schema 至少包含：
  - `masks`：`[T,H,W]` 或 `[T,N,H,W]`，其中 G1 segment 默认 `T=120`、`H=480`、`W=640`。
  - `covered_frames`：已由 SAM3 实际计算并写入的 source frame index。
  - `task`、`episode`、`seg`、`video_path`、`source_fps`、`source_frame_count`。
  - `sam3_model`、`prompt`、`backup_prompt`、`chunk_size`、`chunk_overlap`、
    `output_prob_thresh`。

- 新 G1 blur slice 建议使用 `sam3_blur` 目录，避免与历史 `sam2_blur` artifact 混淆：

```text
training_data/slice/g1_2s61f30/sam3_blur/<task>/ep*/seg*_clip*.mp4
```

- 新 G1 `blur_r2r` pair 可以使用新的显式 duration label 或 step layout 口径，例如：

```text
training_data/pair/blur_r2r/2s61f30_sam3/<task>/
training_data/pair/blur_r2r/2s61f30_slide_sam3/<task>/
```

  若最终选择覆盖维护中的 `2s61f30` 或 `2s61f30_slide` label，必须在正式执行前明确记录
  清理影响和重建命令；不能把 SAM2 与 SAM3 样本混在同一个 pair manifest 中。

- 旧 1s `make_pair.py` 路径仍在仓库中。若后续训练仍会消费
  `training_data/pair/blur_r2r/1s/<G1 task>/`，本任务需要同步提供 SAM3 版本或明确弃用旧
  G1 1s blur；不能让同名 `blur_r2r/1s` 同时包含 G1 SAM2 与 H2R SAM3 且无 manifest 区分。

- 不要求本任务启动正式训练；训练 cache 或 task078 继续推进前，应先完成 SAM3 blur 数据的
  smoke 和全量一致性校验。

## 实施计划（分步骤）

1. 复核现状和基线：
   - 记录 G1 canonical / non-canonical segment、SAM2 mask、`2s61f30` slice、`blur_r2r`
     pair 的当前数量。
   - 抽样读取现有 SAM2 `.npz` 与 H2R SAM3 `.npz` schema，确认 G1 新 artifact 需要的
     frame count、fps、分辨率、值域和 metadata。
   - 明确 task078 当前 step2 仍引用 SAM2 blur；若 task078 尚未生成正式 cache，先暂停
     SAM2 step2 cache 生成，等本任务决定新 SAM3 口径。
2. 做 G1 SAM3 prompt / chunk 可行性 smoke：
   - 从每个 canonical task 选至少 1 个 segment。
   - 候选 prompt 至少包括 `robot arm`、`robotic arm`、`robot`；可按 G1 画面结果增加
     `humanoid robot`、`robot hand`。
   - 使用 SAM3.1、`max_num_objects=1`、`multiplex_count=16`、短 chunk 默认 16 或 17 帧。
   - 不直接人工查看视频/图片；用 mask 非空帧比例、面积均值/方差、与现有 SAM2 mask 的
     IoU/coverage 统计和自动 overlay 产物路径作为判断依据。
3. 新增 `src.pipeline.g1_sam3_precompute`：
   - 使用 `sam3` conda 环境运行。
   - 参数包含 `--task`、`--segment-root`、`--output-root`、`--prompt`、
     `--backup-prompt`、`--chunk-size`、`--chunk-overlap`、`--max-segments-per-task`、
     `--max-segments`、`--resume`、`--dry-run`。
   - 按 segment 读取 30fps `seg*_video.mp4`，把需要的 source frame 拆成短 chunk 调用
     SAM3.1，merge 到全长 `masks[T,H,W]`。
   - `--resume` 必须读取 `covered_frames`；只有现有 artifact 覆盖本次要求的全部 source
     frame 且 shape / metadata 匹配时才跳过。
4. 更新统一运行入口：
   - `scripts/flip_run.sh` 新增 `g1_sam3_precompute`，使用 `SAM3_PYTHON_BIN`。
   - dry-run / smoke / full precompute 示例加入文档。
5. 将 G1 2s blur 生成切到 SAM3：
   - 修改或新增 G1 2s slice 构建入口，使 blur 输入读取
     `training_data/g1_sam3_mask/`。
   - 写出 `sam3_blur` slice，manifest 记录 `control_degrade=sam3_blur`、
     `sam3_mask_path`、prompt、model、chunk 参数。
   - 生成 pair layout 时从 `sam3_blur` hardlink 到 `control_video/`，清晰 original 仍作为
     `video/` target。
   - 不允许 SAM3 mask 缺失时退回 `sam2_blur`。
6. 处理旧 1s G1 blur 口径：
   - 若 1s G1 blur 仍需要维护，给 `make_pair.py` 增加显式 SAM3 mask 口径，或新增独立
     `g1_sam3_blur_pair`。
   - 若 1s G1 blur 不再维护，在文档和脚本 inventory 中标记旧 SAM2 1s 数据为历史产物，
     并明确新训练应使用 2s SAM3 口径。
7. 更新 mask-region eval 读取逻辑：
   - 当前评估入口和 helper 多处命名为 `sam2_mask_root`。如果新 SAM3 blur 仍需要前景/背景
     metrics，应支持从 manifest 的 `sam3_mask_path` 读取，或把 CLI 改为通用
     `--mask-root` / `--mask-kind`。
   - 不能把 SAM3 pair 的 local metrics 静默指向 `training_data/sam2_mask`。
8. 更新文档：
   - `doc/step_5_training_infra.md`：记录 G1 SAM3 blur 的生成顺序、路径、计数和训练口径。
   - `doc/scripts_inventory.md`：新增 G1 SAM3 precompute / blur 入口说明。
   - 新增或扩展 SAM3 文档，记录 G1 prompt/chunk smoke 结论和显存约束。
   - `doc/requirement-log.md` 追加交付记录。
9. 全量生成与校验：
   - 先小样本 smoke，再全量 precompute。
   - 全量 canonical 预期为 5454 个 segment mask；若只生成训练会用到的帧，G1 2s 当前仍应覆盖
     每个 segment 的 0..119 全部 120 帧。
   - 全量 G1 2s SAM3 blur slice / pair 预期为 10908 条。

## 验收标准

- G1 SAM3 mask 预计算入口存在，并可通过 `scripts/flip_run.sh g1_sam3_precompute` 运行。
- `--dry-run` 能输出每个 task 的 segment 数、规划 chunk 数、预期 covered frame 数和输出路径。
- 小样本 SAM3 smoke 产物存在，`.npz` schema 校验通过：
  - `masks` 维度与源 segment frame count / 480x640 对齐。
  - `covered_frames` 覆盖 blur 数据所需全部 source frame。
  - 非空帧比例、面积统计、与 SAM2 baseline 的 IoU/coverage 统计写入 summary。
- G1 2s blur slice 不再写入新的 `sam2_blur` 口径；新产物明确为 `sam3_blur` 或等价
  SAM3 命名。
- 新 `blur_r2r` manifest 中：
  - `control_degrade=sam3_blur`。
  - 存在 `sam3_mask_path`、`sam3_model`、`sam3_prompt`、`sam3_chunk_size` 等字段。
  - 不再把新样本标记为 `sam2_blur`，也不再要求 `sam2_mask_path`。
- 小样本 pair layout 可被 cache/训练读取；如果 eval 启用 mask-region metrics，metrics 读取的是
  SAM3 mask 而不是旧 SAM2 mask。
- 全量 canonical 生成完成后，计数符合预期或在 summary 中解释差异：
  - `g1_sam3_mask`：5454 个 canonical segment mask。
  - `sam3_blur` 2s clips：10908 条。
  - `blur_r2r` SAM3 pair：10908 条。
- 实施后更新相关文档和需求日志；旧 SAM2 blur 数据只作为历史 artifact 说明，不作为新默认训练口径。

### 2026-06-13 扩展 prompt sweep 与 text->bbox 测试

按用户补充要求，只处理 G1 robot segment，不处理 human / H2R 数据，并追加多 prompt 和
两阶段测试：

- 脚本扩展：
  - `src.pipeline.g1_sam3_precompute` 新增 `--prompt-list`，同一次模型加载下跑多组
    robot prompt，并为每个 prompt 写独立 `index.json`，根目录写 `prompt_sweep_index.json`。
  - 新增 `--prompt-mode text_bbox`，第一阶段 text prompt 生成 mask，再从 mask 生成归一化
    bbox，第二阶段重新开 SAM3.1 session 跑 bbox prompt。
  - 新增 `--bbox-include-text`；实测纯 bbox prompt 接口可跑但 17 帧样本输出全空，二阶段
    需要 `bbox + 同 text prompt` 才有实际 mask。
- 7 个 robot-only text prompt sweep：
  - 命令：`g1_sam3_precompute --cuda 1 -- --task all --max-segments-per-task 1 --frame-count 61 --chunk-size 17 --prompt-mode text --prompt-list "robot,robot arm,robot hand,robot body,humanoid robot,Unitree G1 robot,mechanical arm" --backup-prompt "" ...`
  - 结果无 OOM；输出：`tmp/g1_sam3_prompt_sweep_robot_text/`。
  - `robot`：`mean_nonempty_frame_ratio=0.574`、`mean_sam2_iou=0.301`，当前 text-only 最好；
    Collect Clothes 面积约为 SAM2 的 2.29x，Washing Machine 0/61 全空。
  - `mechanical arm`：IoU 0.188，Washing Machine 全空。
  - `robot arm`：IoU 0.123，更像局部 arm mask。
  - `robot hand`：非空率 0.754，但平均面积 0.0052，明显只是局部 hand/夹爪。
  - `robot body`、`humanoid robot`、`Unitree G1 robot`：三任务 smoke 全空。
- text->bbox 二阶段：
  - 命令：`g1_sam3_precompute --cuda 1 -- --task all --max-segments-per-task 1 --frame-count 61 --chunk-size 17 --prompt-mode text_bbox --bbox-include-text --prompt-list "robot,mechanical arm" --backup-prompt "" ...`
  - 结果无 OOM；输出：`tmp/g1_sam3_prompt_sweep_robot_text_bbox/`。
  - `robot`：7 个 chunk 进入 bbox，5 个 chunk text 阶段无 bbox 种子；聚合 IoU 0.302，
    和 text-only 的 0.301 基本持平，Washing Machine 仍全空。
  - `mechanical arm`：聚合 IoU 从 text-only 0.188 提升到 0.232，但 Collect Clothes
    SAM3/SAM2 面积约 2.53x，Washing Machine 仍全空。
- 结论：
  - 61 帧按 17 帧 chunk 可以稳定跑 SAM3.1；单 session 61 帧仍 OOM。
  - 纯 SAM3 text prompt 与当前 text->bbox 二阶段都不能干净替代 SAM2/FK 全身 blur mask。
  - 纯 SAM3.1 在 Washing Machine 上表现一般且不稳定：多数 prompt 全空，`robot arm` /
    `robotic arm` 也只覆盖少量局部帧，不能作为干净的 G1 robot blur mask。
  - 暂不应继续生成全量 `sam3_blur` pair/cache；若继续推进，需要引入更强空间约束或质量控制，
    例如 SAM2/FK bbox seed、point/instance refine、跨 chunk 质量过滤或任务级 prompt 策略。
