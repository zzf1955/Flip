## 背景

task076 已交付 G1 `2s61f30` 基础切片和 pair layout：

- `training_data/slice/g1_2s61f30/original/`：10908 条 robot original。
- `training_data/slice/g1_2s61f30/sam2_blur/`：10908 条 SAM2 blur。
- `training_data/slice/g1_2s61f30/seedance_direct/`：84 条 Seedance direct。
- `training_data/pair/{identity_r2r,blur_r2r,h2r}/2s61f30/`：对应训练 pair。

但当前 `h2r/2s61f30` 的 Seedance 数据仍是 robot-driven 的两窗口切片，不是密集
滑动窗口；同时 task076 明确留下了 `2s61f30` 的 T5/VAE cache 缺口。task077 已把
Seedance 2s 滑动窗口和 `step1/step2` layout 作为单独 pending task 发布，但未覆盖
VAE cache / T5 cache，也没有把三阶段外观编辑训练需要的 pair/cache 口径一起收口。

本任务在 task077 的数据 layout 需求上继续补全：一次性完成 G1 2s Seedance 滑窗切片、
三阶段训练 pair layout、T5 cache 和 VAE cache。为避免混淆与覆盖 task076 的已验证
输出，默认使用新的 duration label `2s61f30_slide` 和新的 step layout 根目录。

## 目标

- 生成 G1 2s Seedance 滑动窗口数据：
  - `step1/origin`：与每个 Seedance 滑窗完全对齐的真实 robot original。
  - `step1/human`：Seedance 4s human source 的 2s 滑窗切片。
- 复用 task076 已验证的 robot-only 数据，发布 Step2 layout：
  - `step2/origin`：真实 robot original。
  - `step2/blur`：SAM2 robot blur。
- 生成三阶段训练使用的 pair layout，默认 duration label 为 `2s61f30_slide`：
  - `identity_r2r`：真实 robot 到真实 robot。
  - `blur_r2r`：模糊 robot 到真实 robot。
  - `h2r`：Seedance human 到真实 robot。
- 为上述 pair layout 补齐 T5 cache 和 VAE cache，并写出可复查的 manifest / summary。
- 不启动正式训练；如需要，仅提供 cache 完整性验证或极小步 smoke 命令。

## 范围

- 数据任务范围限定为当前 G1 三任务：
  - `Inspire_Collect_Clothes_MainCamOnly`
  - `Inspire_Pickup_Pillow_MainCamOnly`
  - `Inspire_Put_Clothes_into_Washing_Machine`
- Seedance 源默认来自：

```text
training_data/seedance_direct/4s/<task>/ep*/seg*_human.mp4
```

- 保持 `2s61f30` 视频口径：30fps、61 帧、Wan `4k+1` 输入长度。
- Seedance 滑窗 stride 必须参数化，默认 `0.5s`；对 4s / 120 帧 robot segment，
  默认窗口起点应为 `0, 15, 30, 45, 59`，其中 `59` 为 tail-aligned 起点。
- 默认输出不覆盖 task076 已有目录：

```text
training_data/slice/g1_2s61f30/
training_data/pair/{identity_r2r,blur_r2r,h2r}/2s61f30/
```

- 新的 step layout 默认写入：

```text
training_data/g1_2s61f30_seedance_slide/
├── step2/
│   ├── origin/
│   └── blur/
└── step1/
    ├── origin/
    └── human/
```

- 新的 pair/cache 默认写入：

```text
training_data/pair/{identity_r2r,blur_r2r,h2r}/2s61f30_slide/
training_data/cache/t5/{identity_r2r,blur_r2r,h2r}/2s61f30_slide/
training_data/cache/vae/{identity_r2r,blur_r2r,h2r}/2s61f30_slide/
```

- 可以 hardlink 复用 task076 中完全同源、同帧序列的视频文件；但新的 manifest 必须
  写入新路径和新 `duration_label`，不能直接复用旧 manifest 代替新数据索引。
- 缺少 Seedance source、robot segment、SAM2 blur、帧数、fps 或配对 metadata 时必须
  直接失败；禁止静默 fallback 到旧 `2s61f30` 或跳过样本。

## 实施计划（分步骤）

1. 复核现有数据与缺口：
   - 读取 task076 的 `training_data/slice/g1_2s61f30/{original,sam2_blur}/index.jsonl`。
   - 读取当前 `training_data/pair/{identity_r2r,blur_r2r,h2r}/2s61f30/` manifest。
   - 扫描三任务 Seedance 4s source，输出 source 数、task 分布、可映射 robot segment 数。
   - 明确记录当前 `h2r=84` 只是两窗口切片，作为滑窗扩展前的 baseline。
2. 实现或扩展 G1 2s Seedance slide 数据构建入口：
   - 推荐新增独立 pipeline 脚本，避免改动 task076 既有默认输出语义。
   - 参数包含 `--task`、`--duration-label`、`--stride-frames/--stride-seconds`、
     `--output-root`、`--pair-root`、`--dry-run`、`--limit-*`。
   - `--dry-run` 必须输出每个 task 的 Step1 / Step2 / pair 规划数量和滑窗起点分布。
3. 生成 Step2 layout：
   - 从 task076 的 original / SAM2 blur 精确 hardlink 或复制到
     `training_data/g1_2s61f30_seedance_slide/step2/{origin,blur}`。
   - 写出新的 Step2 manifest，路径字段指向新 step layout。
   - Step2 样本默认应保持 `origin=10908`、`blur=10908`。
4. 生成 Step1 Seedance 滑窗 specs：
   - 对每个 Seedance 4s source 生成 61 帧窗口。
   - 记录 `source_id`、`source_segment_id`、`task`、`episode`、`seg`、
     `clip_idx`、`clip_start_frame`、`source_frame_indices`、
     `human_source_frame_indices`、`tail_aligned`、`seedance_source_video`。
   - 默认 0.5s stride 下，42 条 4s source 的预期窗口规模约为 210 条；实际数量以
     source 可映射性和 manifest 校验结果为准，但必须显著多于当前 84 条 baseline。
5. 生成 Step1 视频：
   - `step1/human` 从 Seedance 4s mp4 按 `human_source_frame_indices` 取帧并输出
     30fps / 61 帧视频。
   - `step1/origin` 从对应 robot source 按同一时间窗口输出 30fps / 61 帧视频。
   - 对与 task076 已有 original clip 完全同源同帧的窗口允许 hardlink。
6. 发布训练 pair layout：
   - `identity_r2r/2s61f30_slide` 使用 Step2 origin 构造 robot->robot pair。
   - `blur_r2r/2s61f30_slide` 使用 Step2 blur/origin 构造 blur->robot pair。
   - `h2r/2s61f30_slide` 使用 Step1 human/origin 构造 human->robot pair。
   - 每个 pair manifest 必须写入 `data_type`、`duration_label`、`robot_task`、
     `source_id`、`input_video`、`target_video`、`step_layout_source`。
7. 生成 T5 cache：
   - 复用现有训练配置和 prompt schema。
   - 为 `identity_r2r`、`blur_r2r`、`h2r` 三类数据分别生成或确认 T5 prompt cache。
   - cache 输出路径必须带 `2s61f30_slide`，避免和旧 `2s61f30` 混用。
8. 生成 VAE cache：
   - 使用 `scripts/flip_run.sh mitty_cache` 统一入口执行 GPU cache 命令。
   - 对三类 pair layout 分别生成 VAE cache。
   - 支持按 task 断点续跑，但 manifest 计数必须最终与 pair manifest 一致。
9. 校验并记录：
   - 校验所有 pair manifest、T5 cache、VAE cache 的数量一致性。
   - 校验视频 fps、帧数、分辨率、`source_frame_indices` 长度。
   - 生成 `summary.json` 或等价统计文件，记录每个 task 的 Step1/Step2/pair/cache 数量。
   - 更新 `doc/step_5_training_infra.md`、`doc/scripts_inventory.md` 和
     `doc/requirement-log.md`。

## 验收标准

- 新 step layout 存在且不覆盖 task076 原目录：

```text
training_data/g1_2s61f30_seedance_slide/step2/origin/
training_data/g1_2s61f30_seedance_slide/step2/blur/
training_data/g1_2s61f30_seedance_slide/step1/origin/
training_data/g1_2s61f30_seedance_slide/step1/human/
```

- 新 pair/cache 目录存在：

```text
training_data/pair/identity_r2r/2s61f30_slide/
training_data/pair/blur_r2r/2s61f30_slide/
training_data/pair/h2r/2s61f30_slide/
training_data/cache/t5/identity_r2r/2s61f30_slide/
training_data/cache/t5/blur_r2r/2s61f30_slide/
training_data/cache/t5/h2r/2s61f30_slide/
training_data/cache/vae/identity_r2r/2s61f30_slide/
training_data/cache/vae/blur_r2r/2s61f30_slide/
training_data/cache/vae/h2r/2s61f30_slide/
```

- Step2 样本数默认与 task076 保持一致：`origin=10908`、`blur=10908`。
- Step1 `origin` 与 `human` 数量必须完全一致，并且每条 `source_id` 一一配对。
- 默认 0.5s stride 下，Step1 `h2r` 样本应显著多于当前 84 条 baseline；若实际数量
  不是约 210 条，必须在 summary 中解释原因并列出无法映射的 source。
- 所有视频样本必须是 30fps、61 帧、640x480；manifest 中的
  `source_frame_indices` 和 `human_source_frame_indices` 长度必须为 61。
- 三类 pair layout 的 manifest 必须可被训练/cache 代码直接消费，且不引用旧
  `2s61f30` cache 路径。
- T5 cache 对三类数据均存在，prompt hash / negative prompt 文件齐全。
- VAE cache 对三类数据均存在，cache manifest 行数与对应 pair manifest 行数一致。
- `scripts/flip_run.sh mitty_cache` 断点续跑后不会重复写坏已有 cache，也不会把缺失样本
  静默视为成功。
- 交付记录中列出：
  - Step1 / Step2 / pair / cache 的最终计数。
  - 每个 G1 task 的样本数。
  - cache 命令、GPU、耗时、失败重跑记录。
  - 与 task076 `2s61f30` 的路径差异和兼容注意事项。

## 测试要求

- `python -m compileall` 覆盖新增或修改的 pipeline / cache 脚本。
- 数据生成入口的 `--dry-run` 必须通过，并输出：
  - Seedance 4s source 数。
  - Step1 滑窗数量和起点分布。
  - Step2 复用数量。
  - 三类 pair 规划数量。
- 小样本 smoke：
  - 每个 G1 task 至少 1 个 Seedance source。
  - 生成 Step1 origin/human、Step2 origin/blur、三类 pair layout。
  - 用 OpenCV 校验 fps、帧数、分辨率，不直接人工查看视频。
- cache smoke：
  - 对小样本 pair layout 跑 T5 cache 和 VAE cache。
  - 使用 `scripts/flip_run.sh mitty_cache` 入口执行 VAE cache。
  - 校验 cache manifest 与 pair manifest 数量一致。
- 正式生成后校验：
  - 全量 manifest schema。
  - Step1 origin/human 一一配对。
  - Step2 origin/blur 一一配对。
  - pair manifest 与 T5/VAE cache manifest 数量一致。
  - 随机抽查若干 hardlink 样本 inode，确认复用策略符合预期。
- 不要求启动正式训练；如实现中新增训练 preset，可额外运行极小步 dry-run/smoke，
  但不能把训练成功作为本任务 cache 交付的替代。
