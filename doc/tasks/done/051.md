## 背景

当前 `wan_vae_idm` 是基于整段 clip 的 VAE latent 做 action 监督，更适合做视频级一致性
验证，但不适合你现在要的两帧 inverse dynamics。新的 IDM 需要直接回答 frame-to-frame
action transition 问题：给定 `s_t` 和 `s_{t+1}`，预测 `a_t`。同时你希望 arm 和 hand
分开训练两个小网络，避免把两类动作混在一起。

## 目标

1. 新增一个独立的两帧 IDM，不替换现有 `wan_vae_idm`。
2. 明确 action 对齐口径为 `(s_t, s_{t+1}) -> a_t`。
3. 模型输入为两帧图像拼接后的 6 通道张量，使用一个小 CNN 编码。
4. arm 和 hand 使用两个独立的小网络，同一入口训练、保存和评估。
5. 在 Pick up Pillow 上完成 GPU smoke 和完整训练验证。

## 范围

- 仅实现两帧 pair-level IDM，不做整段视频 clip 监督。
- 仅预测 `action.ee_action` 与 `action.hand_cmd`，不引入 `robot_q_desired`。
- arm / hand 共享数据读取和训练循环，但不共享模型参数。
- 新模块保留旧 IDM，不回退、不兼容旧 clip 口径。
- 需要同步更新 `doc/step_5_training_infra.md`、`doc/scripts_inventory.md` 和
  `doc/requirement-log.md`。

## 实施计划（分步骤）

1. 新建 `src/pipeline/wan_pair_idm.py`，实现 pair 数据集、pair 对齐逻辑、arm/hand 双模型
   和训练 / validate / eval CLI。
2. 让数据集从 segment 视频中生成相邻帧 pair，并按 `frame_index=t` 取 `a_t` 作为标签。
3. 设计小 CNN backbone，输出分别接 arm head 和 hand head，训练时分别计算两个 loss。
4. 保存双网络 checkpoint、统计指标和预测表，保证 validate/eval 可复算。
5. 更新文档和 script inventory，记录新模型的输入语义、训练方式和测试命令。
6. 在 `Inspire_Pickup_Pillow_MainCamOnly` 上跑 smoke，再跑 4000 step 完整训练并复算 held-out。

## 验收标准

- 新两帧 IDM 能在 `Inspire_Pickup_Pillow_MainCamOnly` 上跑通 GPU smoke。
- 完整训练能跑到 4000 step，且 held-out 指标优于 mean baseline。
- arm 和 hand 分别输出可解释的指标，且两个网络参数彼此独立。
- 新模块和文档都清楚写明 `(s_t, s_{t+1}) -> a_t` 的动作对齐口径。
