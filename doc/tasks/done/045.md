## 背景

当前 FLIP 的正式 pair 数据已经稳定为 split-free task 级布局：

```text
training_data/pair/<data_type>/<duration>/<robot_task>/
training_data/cache/vae/<data_type>/<duration>/<robot_task>/
```

`make_pair.py` 目前负责从 Seedance/overlay/advance 等 human source 构建
`h2r` / `r2h` pair。该流程已经稳定，不应为了 r2h 微调模型生成数据而继续加重
它的职责。

用户现在已经训练 r2h 模型，需要用该模型批量合成 Human 视频，替代 Seedance 的
human 生成，并将结果落盘为新的 h2r 训练 pair。目标目录应作为独立 syn task，
例如：

```text
training_data/pair/h2r/1s/Inspire_Collect_Clothes_MainCamOnly_syn/
```

这里 `control_video/` 是 r2h 模型生成的 synthetic human，`video/` 是对应真实
robot target。该任务只负责生成和组织 syn pair 数据，不负责后续混合比例训练逻辑。

该任务的 robot 输入来源应以 `training_data/segment/` 为准，而不是以已有 r2h
pair/cache 为准。已有 r2h pair/cache 只代表之前 Seedance 覆盖过的一小部分 robot
来源，不足以作为后续自合成的枚举基准。实现时应直接扫描
`training_data/segment/<task>/<episode>/<seg>_video.mp4`，按目标 duration 切成训练
clip，再送入 r2h 模型生成 synthetic human。

新增约束：robot 来源分成两部分，已经由 Seedance 合成过的来源和本任务自合成来源
不能重叠。当前目录中 episode 命名为 `ep000` 这类格式；Seedance 覆盖集默认按
`ep000`-`ep003` 理解，剩余 episode 才允许进入 r2h 自合成。实现时不能只依赖
输出 task 名区分数据，必须按 robot source 级别校验互斥。

## 目标

1. 新增一条独立的 r2h 离线合成入口，不修改现有 `make_pair.py` 主流程。
2. 使用指定 r2h run/checkpoint，从 `training_data/segment` 枚举得到的 robot
   clips 批量生成 synthetic human 视频。
3. 将生成结果直接组织成当前 `h2r` 训练可消费的 pair 布局。
4. 为每条 syn pair 写入完整 manifest 溯源，能追踪到来源 segment、clip window、
   生成模型和生成参数。
5. 输出数据可以直接交给现有 `src.pipeline.mitty_cache` 生成 VAE/T5 cache。
6. 生成 syn pair 时排除所有 Seedance 已覆盖的 robot 来源，默认排除
   `ep000`-`ep003`，并支持显式传入覆盖集/排除集。

## 范围

包含：

- 新增脚本，例如 `src/pipeline/r2h_synthesize.py`。
- 复用现有 Mitty 模型加载与推理能力，包括：
  - `src.pipeline.eval_mitty.generation.load_model`
  - Mitty denoise 逻辑
  - T5 cache 加载
  - VAE decode 与视频保存工具
- 直接读取 robot segment 来源：
  - `training_data/segment/<source_task>/<episode>/<seg>_video.mp4`
  - 按 `duration` 切成与现有 pair 一致的 clip，例如 1s 时从 4s segment 切出
    4 个非重叠 clip，或按实现配置使用稳定窗口规则。
- 如 r2h 推理需要 latent 输入，脚本应在生成时对 robot clip 做 VAE encode，或先写
  受控的临时/source cache；这部分 cache 只服务合成入口，不作为训练数据 split
  的来源。
- 输出 h2r syn pair：

```text
training_data/pair/h2r/<duration>/<source_task>_syn/
├── video/pair_NNNN.mp4
├── control_video/pair_NNNN.mp4
├── metadata.csv
├── manifest.jsonl
└── pair_order.jsonl
```

- 支持按从 `training_data/segment` 构建的稳定 robot clip 顺序选择样本，至少支持：
  - 全量生成。
  - 按数量生成。
  - 按 head/tail/range 选择。
  - `--resume-existing` 跳过已存在且可解码、帧数/尺寸正确的视频。
- 支持 robot source 互斥过滤：
  - 默认排除 `ep000`、`ep001`、`ep002`、`ep003`。
  - 支持显式参数覆盖，例如 `--exclude-episodes ep000,ep001,ep002,ep003`。
  - 支持从已有 Seedance/original h2r pair manifest 中读取已覆盖 robot source；
    这些 manifest 只用于排除和校验，不作为主要 robot 输入来源。
  - 输出前校验 syn manifest 中不存在 Seedance 覆盖集内的 robot source。
- manifest 至少记录：
  - `data_type: h2r`
  - `robot_task: <source_task>_syn`
  - `source_robot_task: <source_task>`
  - `synthetic_source: mitty_r2h`
  - `generator_run`
  - `generator_checkpoint`
  - `generator_num_inference_steps`
  - `generator_cfg_scale`
  - `source_robot_clip_id`
  - `source_order_index`，表示在 segment 枚举列表中的稳定顺序
  - `source_segment_path`
  - `source_clip_start`
  - `source_clip_dur`
  - `source_clip_index`
  - `robot_source_key`，用于跨 Seedance/syn 数据校验 robot 来源不重叠
  - `seedance_excluded: true/false` 或等效字段，记录该条是否经过排除集校验
  - `source_id`，由 `robot_source_key` 派生并追加 `_syn`

不包含：

- 不实现原始数据与 syn 数据的混合比例训练；该部分由任务 046 负责。
- 不修改现有 `src.pipeline.runtime_data`、`src.pipeline.train`、
  `src.pipeline.train_mitty` 的默认数据选择逻辑。
- 不重新训练 r2h 模型本身。
- 不修改 Seedance API、SAM2、retarget、SMPLH 或 inpaint 算法。
- 不把 syn 数据混入原始 task 目录；必须作为独立 `_syn` task/source 落盘。
- 不自动删除或覆盖已有 `training_data/pair`、`training_data/cache` 目录；清理必须
  由用户显式传参触发，并限制在目标 `_syn` 输出目录内。

## 实施计划（分步骤）

1. 定义 `training_data/segment` robot clip 记录到 h2r syn manifest 的字段映射。
2. 新增 `src/pipeline/r2h_synthesize.py` CLI：
   - `--source-task`
   - `--duration`
   - `--run`
   - `--checkpoint`
   - `--segment-root`
   - `--output-pair-root`
   - `--num-samples` / `--range` / `--tail` / `--head`
   - `--exclude-episodes`
   - `--seedance-covered-manifest`
   - `--resume-existing`
   - `--num-inference-steps`
   - `--cfg-scale`
3. 从 `training_data/segment` 构建 robot clip 列表：
   - 枚举 `<task>/<episode>/<seg>_video.mp4`。
   - 按 duration 生成稳定 `robot_source_key`，包含 task、episode、seg、clip index
     或 clip start。
   - 校验 segment 视频存在且可解码。
   - 对列表排序，保证多次运行选择顺序稳定。
4. 构建 Seedance 覆盖 robot source 集合：
   - 默认 episode 覆盖集为 `ep000`-`ep003`。
   - 若传入已有 original/Seedance h2r manifest，则从 manifest 提取
     `robot_source_key` 或等价字段作为覆盖集。
   - source 样本命中覆盖集时直接排除，不进入生成队列。
5. 加载 r2h 模型与 T5 cache，按过滤后的稳定顺序生成 synthetic human。
6. 写出 h2r syn pair：
   - `control_video/pair_NNNN.mp4` 写生成 human。
   - `video/pair_NNNN.mp4` 写真实 robot target，来自 `training_data/segment`
     切出的同一个 robot clip。
   - `metadata.csv` 使用现有 prompt。
   - `manifest.jsonl` 写完整溯源字段。
   - `pair_order.jsonl` 为 syn task 生成独立稳定顺序表。
7. 增加输出完整性校验：
   - 视频可解码。
   - 帧数与尺寸和 source 对齐。
   - `metadata.csv`、`manifest.jsonl`、实际视频文件数量一致。
   - syn manifest 的 robot source 与 Seedance 覆盖集无交集。
8. 更新文档：
   - 在 `doc/step_5_training_infra.md` 说明 r2h synth -> h2r syn pair -> mitty_cache。
   - 在 `doc/scripts_inventory.md` 登记新入口。

## 验收标准

1. 可以用指定 r2h checkpoint 对一个 source task 生成 syn h2r pair，例如：

```text
training_data/pair/h2r/1s/Inspire_Collect_Clothes_MainCamOnly_syn/
├── video/pair_0000.mp4
├── control_video/pair_0000.mp4
├── metadata.csv
├── manifest.jsonl
└── pair_order.jsonl
```

2. `manifest.jsonl` 中每条记录都能追踪到 `training_data/segment` 下的 source
   segment、clip start/duration/index、robot source key 和 generator checkpoint。
3. 对 `_syn` task 运行现有 `src.pipeline.mitty_cache` 后可生成：

```text
training_data/cache/vae/h2r/1s/Inspire_Collect_Clothes_MainCamOnly_syn/
├── pair_0000.pth
└── manifest.jsonl
```

4. 生成入口发现 source segment 缺失/不可解码、输出视频损坏、帧数或尺寸不匹配时
   直接报错。
5. 生成入口默认不会使用 `ep000`-`ep003` robot source；如果传入 Seedance/original
   manifest，syn 输出的 `robot_source_key` 与该覆盖集必须无交集。
6. 现有 `make_pair.py`、训练入口和 runtime data 默认逻辑不发生行为变化。
