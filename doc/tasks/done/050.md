## 背景

H2R 外观编辑实验已经在当前三个任务上产出了 Baseline 和 Ours 的生成视频。现在需要用
IDM 模型判断这些生成视频是否真的学到了 action：分别从真实 robot 视频和生成 robot
视频中提取 action，再和原始 GT action 比较。评价口径应回答两个问题：

- 生成视频提取出的 action 距离 GT action 有多远。
- 生成视频提取出的 action 是否接近真实视频提取出的 action，并且 Ours 是否优于 Baseline。

## 目标

1. 对两个 H2R 外观编辑 checkpoint 的 `full_eval` 视频运行 IDM action 评估。
2. 对每个样本输出 `target_action`、`gt_video_pred_action`、`gen_video_pred_action` 及对应误差。
3. 汇总 Baseline vs Ours 在三任务、in-task / OOD split 上的 action 差距。
4. 只跑当前三个任务，不扩展到其它任务。

## 输入与任务范围

Baseline run：

```text
training_data/log/final_mitty_0507_004901-h2r_1s-400d_r96_self_qkv_1000s_0507_004922
```

Ours run：

```text
training_data/log/final_ours_step3_0507_004839-h2r_1s-400d_r96_self_qkvo_ffn_1000s_0507_051842
```

评估目录：

- `<run>/full_eval/in_task_eval`
- `<run>/full_eval/ood_eval`
- `<run>/full_eval/data_split/in_task_eval.jsonl`
- `<run>/full_eval/data_split/ood_eval.jsonl`

仅允许以下任务进入统计：

- `Inspire_Collect_Clothes_MainCamOnly`（当前 in-task，已有记录约 16 条）
- `Inspire_Put_Clothes_into_Washing_Machine` / `Inspire_Put_Clothes_into_Washing_Machine_MainCamOnly`（当前 in-task，已有记录约 64 条）
- `Inspire_Pickup_Pillow_MainCamOnly`（当前 OOD，已有记录约 42 条）

不要跑 `Inspire_Put_Clothes_Into_Basket` 或其它旧任务。若 records 中出现上述列表外任务，
脚本应明确报错或要求显式过滤，不要静默纳入 summary。

## IDM checkpoint 口径

- 使用 task47 / task48 已训练的三任务 Wan VAE IDM checkpoint，或 task49 交付的 masked IDM
  checkpoint；同一次 Baseline/Ours 对比中必须使用同一套 checkpoint 口径。
- 建议把最终使用的 checkpoint 复制或登记到稳定输出目录，例如
  `output/wan_vae_idm/checkpoints/<task>/best_checkpoint.pt`，避免依赖临时 worktree 路径。
- 当前可参考的已有 checkpoint 路径：
  - `.worktrees/t047/tmp/wan_vae_idm_collect_stride05_s4000_arm2_cosine/best_checkpoint.pt`
  - `.worktrees/t048/tmp/wan_vae_idm_wash_stride05_s4000_arm2_cosine/best_checkpoint.pt`
  - `.worktrees/t048/tmp/wan_vae_idm_pillow_stride05_s4000_arm2_cosine/best_checkpoint.pt`

## 实施计划

1. 检查两个 run 的 `full_eval` 目录、`gen_*.mp4` / `gt_*.mp4` 和 `data_split/*.jsonl` 是否完整。
2. 如果现有 `wan_vae_idm eval` 只能处理单任务单 checkpoint，新增一个三任务 eval driver 或扩展
   CLI：按 `robot_task` 分组 records，并为每个任务选择对应 IDM checkpoint。
3. 为 Washing Machine 任务实现显式 alias 映射，处理 eval records 中无 `MainCamOnly` 后缀、
   但训练 checkpoint / 数据目录可能使用 `MainCamOnly` 后缀的情况。
4. 每个样本输出：
   - `target_action`：从原始 LeRobot action 解析出的 GT action。
   - `gt_video_pred_action`：IDM 从 `gt_*.mp4` 预测的 action。
   - `gen_video_pred_action`：IDM 从 `gen_*.mp4` 预测的 action。
   - `gt_video_to_target_mse`、`gen_video_to_target_mse`、`gen_video_to_gt_video_mse`。
   - arm / hand / combined 分组指标；若使用 task49 masked IDM，也输出 masked 指标和 visible ratio。
5. 对 Baseline 和 Ours 分别运行 `in_task_eval` 与 `ood_eval` 全量评估，只保留上述三个任务。
6. 生成对比 summary：按 `run`、`split`、`task` 汇总均值、中位数、样本数，并额外输出
   Ours - Baseline 的 delta 表。
7. 在任务文档或相关实验文档中记录最终使用的 IDM checkpoint、命令、输出路径和核心结论。

## 输出要求

建议输出到：

```text
output/idm_h2r_action_eval/<run-name>/
```

至少包含：

- `per_sample_actions.jsonl` 或 `.npz`：保存 target / gt_video_pred / gen_video_pred action 向量。
- `per_sample_metrics.csv`：逐样本 action error。
- `summary_by_task.csv`：按 run / split / task 汇总。
- `summary_compare_baseline_ours.csv`：Baseline 与 Ours 的差值比较。
- `config.json`：记录 run 路径、split、task filter、IDM checkpoint 路径、是否 masked。

## 验收标准

- 两个指定 run 均完成 `in_task_eval` 和 `ood_eval` 的 IDM action 评估。
- 汇总结果只包含 Collect Clothes、Washing Machine、Pickup Pillow 三个任务。
- 每条样本都能追溯到 records 中的 `robot_task`、`episode`、`seg`、`clip_start`、`clip_dur`。
- 输出中能同时比较：
  - 真实视频预测 action vs GT action；
  - 生成视频预测 action vs GT action；
  - 生成视频预测 action vs 真实视频预测 action。
- 报告明确说明 Ours 相比 Baseline 在 arm、hand、combined 指标上是改善、持平还是变差。
- 缺少视频、records、checkpoint 或任务 alias 不明确时直接失败，不做隐式 fallback。

## 测试要求

- `python -m compileall` 覆盖新增 / 修改的 Python 模块。
- 新增或扩展 CLI 的 `--help` smoke。
- `--max-samples` 小样本 smoke：每个 run 至少覆盖 in-task 和 OOD 各 1 条，确认输出字段完整。
- 全量三任务评估：两个 run 的 80 条 in-task + 42 条 OOD 记录，按任务汇总。
