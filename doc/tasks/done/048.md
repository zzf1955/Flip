## 背景

当前 `src.pipeline.wan_vae_idm` 已在 `Inspire_Collect_Clothes_MainCamOnly`
上训练并验证 arm-hand Video2Action IDM。用户希望在另外两个任务上也试一下：

- `Inspire_Pickup_Pillow_MainCamOnly`
- `Inspire_Put_Clothes_into_Washing_Machine_MainCamOnly`

现有脚本把任务路径硬编码为 Collect Clothes，需要改成可通过 CLI 指定任务。

## 目标

1. 让 Wan VAE IDM 训练/验证/eval 支持指定 task short/full name。
2. 分别在 Pick Up Pillow 和 Put Clothes into Washing Machine 两个任务上训练并验证。
3. 输出 loss 曲线、best checkpoint、held-out metrics 和预测检查结果，判断 loss 是否正常下降、是否出现均值坍缩。

## 范围

- 修改 `src/pipeline/wan_vae_idm.py` 的任务路径配置。
- 修改 `doc/step_5_training_infra.md` 和脚本清单中对应说明。
- 在两个任务上运行小规模到中等规模训练验证。

## 实施计划

1. 增加 `--task-short` 和可选 `--task-full` 参数，默认保持 Collect Clothes 行为不变。
2. 将 `ActionResolver`、clip discovery、validate/eval 的数据根目录统一从 CLI 配置解析。
3. 运行 CLI/compile 级别检查。
4. 分别对两个新任务运行训练，使用 episode split，记录 train/eval loss。
5. 使用 best checkpoint 做 full held-out validate，并汇总 MSE、MAE、相对误差和 std ratio。

## 验收标准

- `scripts/flip_run.sh wan_vae_idm -- train --help` 正常显示 task 参数。
- Collect Clothes 默认路径不破坏。
- 两个新任务均能产出 `best_checkpoint.pt`、`eval_loss.csv`、`loss_curve.png`、`validate_all/val_metrics.json`。
- 汇报两个任务 held-out loss、相对误差和是否均值坍缩。

## 测试要求

- `python -m compileall src/pipeline/wan_vae_idm.py`
- `scripts/flip_run.sh wan_vae_idm -- train --help`
- 两个任务的训练和 best checkpoint full validate。
