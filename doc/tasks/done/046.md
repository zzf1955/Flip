## 背景

当前 `src.pipeline.runtime_data`、`src.pipeline.train` 和 `src.pipeline.train_mitty`
已经稳定支持 split-free task 级训练数据。现有训练逻辑会按 task 可用样本量比例分配
`train_size`，并从各 task 的 `pair_order.jsonl` 尾部选取 eval。

用户接下来会反复调整 h2r 训练数据配比，例如：

```text
原始 h2r 数据 N 条 + r2h 模型生成的 syn h2r 数据 M 条
```

这个实验入口需要保持和现有训练入口隔离：新逻辑只在新 task / 新入口中实现，不影响
当前稳定训练、评估和 runtime data 逻辑。

同时 eval 集必须稳定。当前已经使用过一套固定评估配置：in-task eval 80 条，OOD
eval 42 条。后续混合训练应继续从原始数据的 `pair_order.jsonl` 尾部倒着选出同一套
80 + 42 eval，保持跨实验对比一致。syn 数据只进入 training，不进入 eval。

另一个硬约束是 robot 来源不能重叠：原始 h2r 数据来自 Seedance 已合成过的 robot
来源，自合成 syn 数据来自任务 045 从 `training_data/segment` 剩余 episode 枚举出的
robot clips。mixed h2r 入口必须校验 original 与 syn 的 `robot_source_key` 无交集，
避免同一段 robot 同时以 Seedance human 和自合成 human 两种来源参与训练。

## 目标

1. 新增独立的混合 h2r 训练入口，不修改现有训练入口默认行为。
2. 支持显式指定训练数据组成：多少条原始 h2r 数据、多少条 syn h2r 数据。
3. 固定 eval 选择逻辑：
   - in-task eval 从原始 h2r task 的 `pair_order.jsonl` 尾部按当前 80 条配置选取。
   - OOD eval 从原始 OOD task 的 `pair_order.jsonl` 尾部按当前 42 条配置选取。
   - syn task 不进入 eval。
4. train 数据不能与稳定 eval 集重叠。
5. original 与 syn 训练数据的 robot 来源不能重叠。
6. 输出 run 的 `data_split/` 完整记录原始/syn 训练数量、稳定 eval 数量、
   `pair_order` 路径和实际样本列表。

## 范围

包含：

- 新增独立 runtime split 模块或入口，例如：
  - `src/pipeline/runtime_mixed_h2r.py`
  - `src/pipeline/train_mitty_mixed_h2r.py`
  - 或一个 wrapper 脚本，调用现有 `train_mitty.py` 前先生成显式 cache list。
- 新入口只服务 h2r mixed training，不泛化改造当前所有 data type。
- 支持原始 task 与 syn task 分开配置，例如：

```text
original train tasks:
  Inspire_Collect_Clothes_MainCamOnly
  Inspire_Put_Clothes_into_Washing_Machine

syn train tasks:
  Inspire_Collect_Clothes_MainCamOnly_syn
  Inspire_Put_Clothes_into_Washing_Machine_syn

ood eval tasks:
  Inspire_Pickup_Pillow_MainCamOnly
```

- 支持用明确数量控制训练样本，例如：

```text
--original-train-size 400
--syn-train-size 400
--in-task-eval-size 80
--ood-eval-size 42
```

- 原始训练样本从原始 in-task `pair_order.jsonl` 中选取时，必须排除尾部稳定 eval
  集合。
- syn 训练样本从 syn task 的 `pair_order.jsonl` 中选取；syn 不参与 eval tail
  计算。
- original/syn 样本选择后必须按 `robot_source_key` 校验互斥；如果旧 manifest
  缺少该字段，入口应从 `source_id`、`source_segment_id`、`episode`、`seg`、
  `clip_idx`、`clip_start` 等字段构造等价 key，构造失败则直接报错。
- `data_split/config.json` 记录：
  - `mode: mixed_h2r`
  - original train tasks
  - syn train tasks
  - ood eval tasks
  - original train size
  - syn train size
  - in-task eval size 80
  - OOD eval size 42
  - 每个 task 的实际 train/eval 计数
  - 每个 task 的 pair_order path
  - 生成时间和 data seed

不包含：

- 不修改 `src.pipeline.runtime_data` 的现有默认分配逻辑。
- 不修改 `src.pipeline.train` / `src.pipeline.train_mitty` 的现有 CLI 语义。
- 不让 syn 数据进入 in-task eval 或 OOD eval。
- 不重新生成 syn pair；syn pair 生成由任务 045 负责。
- 不改变已经稳定的 80 + 42 eval 定义，除非用户显式要求新配置。

## 实施计划（分步骤）

1. 设计 mixed h2r split builder：
   - 读取原始 h2r pair/cache/order。
   - 读取 syn h2r pair/cache/order。
   - 读取 OOD 原始 h2r pair/cache/order。
   - 校验 pair/cache/order 一致。
2. 固定 eval 集选择：
   - 对原始 in-task task，按现有 count-based tail 逻辑分配 80 条 eval。
   - 对 OOD task，按现有 count-based tail 逻辑分配 42 条 eval。
   - 将 eval `pair_id` 集合作为训练排除集。
3. 训练集选择：
   - 从原始 in-task task 的非 eval 区域选择 `--original-train-size` 条。
   - 从 syn task 选择 `--syn-train-size` 条。
   - 支持按 task 容量比例分配，也可预留后续扩展为 per-task 精确数量。
4. 新增独立训练入口：
   - 方案 A：新增 `src.pipeline.train_mitty_mixed_h2r`，内部复用
     `train_mitty.py` 的模型训练能力，但替换 data split 构建。
   - 方案 B：新增 split/list 生成器，输出显式 train/eval/ood cache list，然后
     调用现有 `train_mitty.py --cache-train --cache-eval --cache-ood`。
   - 实施时优先选择改动面更小、与现有稳定入口隔离更清楚的方案。
5. 写出 `data_split/`：
   - `train.jsonl` 同时包含 original 与 syn 记录，并标记 `mix_source`。
   - `in_task_eval.jsonl` 只包含 original 记录。
   - `ood_eval.jsonl` 只包含 original OOD 记录。
   - `config.json` 记录完整混合配置。
6. 增加 CLI 与校验：
   - 容量不足直接报错。
   - original/syn task 名错误直接报错。
   - eval 与 train 发生 `pair_id` 重叠直接报错。
   - original 与 syn 的 `robot_source_key` 重叠直接报错。
   - syn task 出现在 eval 配置中直接报错。
7. 更新文档：
   - 在 `doc/step_5_training_infra.md` 增加 mixed h2r 训练命令示例。
   - 在 `doc/scripts_inventory.md` 登记新入口。
   - 明确该入口与现有训练入口隔离，现有逻辑不动。

## 验收标准

1. 新入口能用原始 h2r cache 与 `_syn` h2r cache 构建训练 split。
2. 默认推荐配置使用稳定 eval：

```text
in-task eval: 80
OOD eval: 42
```

并且 eval 样本来自原始 task 的 `pair_order.jsonl` 尾部。

3. syn 数据只出现在 `train.jsonl`，不会出现在 `in_task_eval.jsonl` 或
   `ood_eval.jsonl`。
4. original 与 syn 训练记录的 `robot_source_key` 无交集；若检测到同一 robot 来源
   被 Seedance 和自合成同时使用，新入口直接失败。
5. 可以通过 CLI 指定训练组成，例如：

```text
original train: 400
syn train: 400
```

6. `data_split/config.json` 清楚记录 mixed h2r 配置、每类数据实际数量和所有
   `pair_order` 路径。
7. 现有 `src.pipeline.runtime_data`、`src.pipeline.train`、`src.pipeline.train_mitty`
   不传新入口时行为不变。
