## 背景

当前训练入口从 split-free cache manifest 在运行时抽取 train / in-task eval / OOD eval。现有实现会按 `source_segment_id` 留出 eval pool，并在 eval video 采样时把 step 纳入 seed，导致同一次训练不同 eval step 的视频样本可能不同；同时 `--train-size` 从合并后的 train pool 抽样，不会在日志中清晰展示每个 task 实际选了多少训练数据。

新的实验要求是在每个 task 的 pair 目录下生成一次固定乱序表，例如 `training_data/pair/blur_r2r/1s/Inspire_Collect_Clothes_MainCamOnly/` 内保存该 task 的 pair 顺序。训练每次从对应顺序表取数据，按 pair 直接划分，不再按 segment 分组。

## 目标

- 为每个 task 的 pair 目录生成可复现、只需生成一次的 pair 顺序表。
- 训练数据选择以该顺序表为唯一顺序来源，并映射到对应 VAE cache 文件。
- `--train-size` 按各 train task 可用数据比例分配到每个 task，再从各自顺序表头部取训练数据。
- in-task eval 从各 train task 顺序表尾部取，保证与训练前缀分离。
- OOD eval 从 OOD task 顺序表尾部或固定位置取，保证跨 eval step 固定。
- 训练启动时打印每个 train / in-task eval / OOD task 实际选取的样本数。

## 范围

- 修改 `src.pipeline.runtime_data` 的运行时 split 构造逻辑。
- 如需要，新增生成/校验顺序表的辅助函数或 CLI。
- 修改 `src.pipeline.train` 的启动日志，输出 per-task 数据量摘要。
- 补充针对顺序表生成、比例分配、train/eval 分离和 eval video 固定性的测试。
- 更新训练基础设施文档和 `doc/requirement-log.md`。

不包含：

- 不改 VAE / T5 cache 文件格式。
- 不按 `source_segment_id` 做分组切分。
- 不改变模型训练 loss、优化器、DDP 同步逻辑。

## 实施计划

1. 梳理 pair manifest 与 cache manifest 的字段对应关系，确定顺序表字段和存放文件名。
2. 在 task pair 目录下生成固定顺序表；若文件已存在则读取并校验，不重新洗牌。
3. 用顺序表顺序驱动 runtime split：train task 从头部按比例取 train，in-task eval 从尾部取 eval，OOD eval 固定取样。
4. 调整 eval video 子采样，不再随 step 改变样本。
5. 在训练日志和写出的 `data_split/config.json` 中记录 per-task 选择数量与顺序表路径。
6. 更新文档说明新划分规则、顺序表位置、复现语义和常用参数。
7. 运行单元测试与轻量静态验证。

## 验收标准

- 每个使用到的 task pair 目录下存在固定 pair 顺序表，训练会复用该表。
- 相同数据、相同 `--data-seed` 与相同参数下，train/eval/OOD 选择完全一致。
- 同一个 run 的不同 eval step 使用同一批 eval video 样本。
- `--train-size` 会按 train task 可用数据比例分配，并在训练日志中打印每个 task 的训练样本数。
- train 与 in-task eval 不重叠；OOD eval 与 train task 分离。
- 文档包含顺序表位置、生成时机和划分规则。

- 测试 in-task train/eval 分离与 eval video step 不变性。
