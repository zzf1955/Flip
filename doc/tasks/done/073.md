## 背景

task071 / task072 已经完成 H2R top-level 1157 episode 的 robot-only WAM cache、
1000-step baseline 与短调参 sweep。task072 使用同一个全量 cache 作为 train/eval 数据源，
并用少量 eval batches 做快速比较；这只能判断短训趋势，不能作为固定测试集口径下的完整训练结果。

用户要求本轮改为：

1. 先划分固定测试集。
2. eval 分为 OOD task 和训练 task held-out 两部分。
3. 每次训练都按固定 eval loss 判断，loss 越低越好。
4. 做完整训练 + 调参，而不是只跑 1000-step smoke/sweep。

本任务依赖 task070 的 `src.pipeline.robot_wam` 入口。当前 `robot_wam` 代码仍在
`.worktrees/t070` / `feat/t070-robot-only-wam-cache-prefetch`，尚未合并到 `main`；
因此本任务继续在 `.worktrees/t070` 实现和运行，数据与输出仍写主仓库绝对路径
`/disk_n/zzf/flip/training_data/...`。

## 目标

1. 为 `training_data/cache/vae/robot_wam/h2r_top1157_s8_160x320` 生成固定 split：
   - train：训练 task 中未 held out 的 episode 样本。
   - eval_in_task：训练 task 中固定 held-out episode 样本。
   - eval_ood：完整 OOD task 样本，OOD task 不进入 train。
2. `train-wan` 支持同时读取 train / in-task eval / OOD eval split，并在日志中分别输出：
   - `eval_in_task_loss` / `eval_in_task_video_loss` / `eval_in_task_action_loss`
   - `eval_ood_loss` / `eval_ood_video_loss` / `eval_ood_action_loss`
   - `eval_mean_loss` 作为默认 best checkpoint 选择指标。
3. 修复 trainable-only checkpoint 初始化 / 恢复，使 LoRA、`state_encoder`、
   `action_decoder` 都能一起恢复，用于继续训练和 eval-only。
4. 跑完整训练与调参：
   - 至少完成 1 个推荐配置的完整训练 run。
   - 至少完成 2 个可比较调参 run 或 continuation run。
   - 每个 run 使用同一固定 split 和同一 eval 口径。
5. 产出 summary 表，按固定 eval loss 排序，给出下一轮推荐。

## Split 设计

初始 OOD task：

- `roll`
- `push_box_random_v1`
- `push_box_two_v1`
- `grab_cube2_v1`

训练 task：

- 其余 H2R top-level task。

训练 task 的 in-task eval 使用 episode-level holdout，默认每个 train task 按 episode
稳定排序后取尾部 10%，且每个 task 至少 1 个 held-out episode。这样避免同一 episode
内相邻滑窗同时出现在 train 和 eval，降低 temporal leakage。

Split artifact 输出：

```text
training_data/robot_wam/splits/h2r_top1157_s8_fixed_v1/
├── train.jsonl
├── eval_in_task.jsonl
├── eval_ood.jsonl
└── summary.json
```

注意：训练内 eval 为了控制耗时，每个 eval split 最多抽样 512 条；完整 eval 覆盖

已经明显下降，但 OOD action loss 很高，说明当前模型主要学到训练 task / held-out episode
分布，对 task-level OOD 泛化不足。后续比较应同时报告训练内抽样 best 和完整 fixed eval，
不能只用 512-sample eval 代表 OOD 全量表现。

### 结论

- 当前推荐 checkpoint：`r16_lr1e-4_aw1_s39024_eval512/best_checkpoint.safetensors`。
- 若继续优化，优先围绕 OOD：
  - 增大 OOD-like task 覆盖或重新设计 train/OOD task 组合。
  - 降低训练内 eval 抽样噪声，例如固定更大 `--max-eval-samples` 或周期性运行完整 eval。
  - 单独分析 `eval_ood` 四个 task 的 action loss 分布，定位是否由少数 task/episode 主导。
