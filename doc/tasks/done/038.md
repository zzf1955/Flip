## 背景

当前 H2R / 三阶段 LoRA 搜索依赖多个分散的 shell 脚本，LoRA merge、数据量、layout、rank、CUDA 分配、日志命名等参数散落在脚本内，难以稳定复现实验并比较相同数据量下不同 LoRA layout 的性能。

## 目标

- 提供统一训练搜索入口，支持按 `LoRA layout × LoRA rank` 展开实验。
- 支持指定要合并的 LoRA checkpoint，并依赖训练入口自动检测 merge LoRA 的位置和 rank。
- 支持指定训练数据类型/任务 preset、train size 与评估规模。
- 支持指定 LoRA layout 与 rank，包括仅 qkv、不含 o 的 layout。
- 支持指定 CUDA 列表，并在这些 GPU 上顺序分配实验。
- 实验 log 目录名与 W&B run name 包含日期/时间、rank 与 layout 短名。

## 范围

- 新增或重写训练搜索脚本，优先用 Python 维护复杂参数组合。
- 保留训练主入口 `src.pipeline.train` 的现有语义，不改训练核心行为，除非脚本需要补齐参数。
- 更新训练基础设施文档与脚本索引。

## 实施计划

1. 梳理现有 H2R LoRA grid shell 脚本和 `src.pipeline.train` 参数。
2. 实现统一 grid launcher，提供清晰 CLI 参数、layout 解析、CUDA 分配、dry-run 与命令打印。
3. 用 layout 短名生成 `--run-prefix` / `--wandb-run-name` / W&B tags。
4. 更新文档说明常用命令和 layout 命名。
5. 运行 dry-run 或静态验证，确认命令展开正确。

## 验收标准

- 可通过一个脚本配置 merge LoRA、task/data preset、train size、layout、rank、CUDA。
- `qkv` layout 能表达 self/cross attention 的 q/k/v 且不包含 o。
- 每个实验分配单个 CUDA，按 CUDA 列表轮转顺序执行；dry-run 不启动训练。
- 生成的训练命令包含时间戳、rank、layout 短名，并传入 W&B run name/tags。
- 文档包含示例命令和参数说明。

## 测试要求

- 运行 launcher 的 `--dry-run` 覆盖至少两个 layout 和两个 rank。
- 如有语法检查工具，执行 Python 编译检查。
