## 背景

task071 已基于 H2R v1 top-level episode 完成 robot-only WAM 的 T5/VAE cache 与
`train-wan` 基线训练：

- 数据范围：`/disk_n/zzf/flip/data/h2r/v1/data/<task>/episode_*.hdf5`
- top-level episode 文件数：1157，其中 1155 个 episode 可产生样本。
- 样本数：48,648。
- T5 cache：`training_data/cache/t5/robot_wam_h2r_top1157_s8`
- VAE cache：`training_data/cache/vae/robot_wam/h2r_top1157_s8_160x320`
- baseline 输出：`training_data/log/robot_wam/h2r_top1157_s8_wan_lora`
- baseline 配置：`lora_rank=16`、`lr=1e-4`、`action_loss_weight=1.0`、
  `video_loss_weight=1.0`、`state_tokens=4`、`max_steps=1000`。
- baseline best/final eval：`eval_loss=1145.6176`、
  `eval_video_loss=0.1041`、`eval_action_loss=1145.5135`。

当前 action loss 数值远大于 video loss，后续需要系统调参，明确更合适的 learning rate、
LoRA rank、loss 权重和训练步数，并输出可比较的实验表。

本任务依赖 task070 的 `src.pipeline.robot_wam` 入口。若 task070 尚未合并到 `main`，
执行时应从 `feat/t070-robot-only-wam-cache-prefetch` 分支继续开任务分支，或在
`.worktrees/t070` 的基础上运行实验；不得在缺少 `robot_wam` 入口的 `main` 上直接启动。

## 目标

1. 复用 task071 已生成的 T5/VAE cache，不重复预制 cache。
2. 跑一组可控的 `train-wan` 调参实验，比较 loss、吞吐、显存和 checkpoint。
3. 产出统一实验汇总表，给出下一轮推荐配置。
4. 保持 robot-only IO：训练和 checkpoint 中不得出现 `human_*` / `control_*` 字段。

## 范围

包括：

- 设计并执行 `train-wan` 调参矩阵。
- 每个 run 独立输出到
  `training_data/log/robot_wam/h2r_top1157_s8_tune/<run_name>/`。
- 汇总每个 run 的配置、best eval、final train、step time、checkpoint 路径和大小。
- 对 best checkpoint 做 key 审计，确认只包含 LoRA、`state_encoder`、`action_decoder`。
- 必要时新增轻量脚本或文档，用于汇总 `train_log.jsonl` / `train_summary.json`。

不包括：

- 不重新构建 H2R manifest。
- 不重新跑 T5/VAE cache，除非发现 task071 cache 损坏。
- 不加入 nested `writing/*` / `cloth/*` episode。
- 不改 robot-only cache schema。
- 不做 rollout 视频评估或真实机器人闭环。

## 实施计划（分步骤）

1. 前置核对：
   - 确认 T5 cache 目录存在且包含 `prompt_75e08935.pth`。
   - 确认 VAE cache `.pth` 文件数为 48,648，`manifest.jsonl` 行数为 48,648。
   - 确认 baseline run 的 `config.json`、`train_summary.json`、`best_summary.json` 存在。
2. 建立调参输出目录：
   - `training_data/log/robot_wam/h2r_top1157_s8_tune/`
   - 每个 run 用稳定命名，例如
     `r16_lr1e-4_aw1_s2k`、`r16_lr5e-5_aw1_s2k`。
3. 第一阶段短 sweep：
   - 固定 `lora_rank=16`、`state_tokens=4`、`batch_size=1`。
   - 比较 `lr={5e-5,1e-4,2e-4}`。
   - 比较 `action_loss_weight={1.0,0.1,0.01}`。
   - 每个配置先跑 `max_steps=1000`，`eval_every=100`，`save_steps=250`。
4. 第二阶段重点复跑：
   - 选择第一阶段 best 2-3 个配置继续到 `max_steps=3000` 或新 run 跑 3000 steps。
   - 若 24GB 单卡显存稳定，再尝试 `lora_rank=32` 与 `state_tokens=8` 的少量对照。
5. 结果汇总：
   - 汇总 CSV/Markdown 至
     `training_data/log/robot_wam/h2r_top1157_s8_tune/summary.csv`
     和
     `training_data/log/robot_wam/h2r_top1157_s8_tune/summary.md`。
   - 字段至少包括：`run_name`、`lora_rank`、`lr`、`action_loss_weight`、
     `video_loss_weight`、`state_tokens`、`max_steps`、`best_step`、`best_eval_loss`、
     `best_eval_video_loss`、`best_eval_action_loss`、`final_train_loss`、
     `avg_step_time_s`、`checkpoint_path`、`checkpoint_size`。
6. 任务收尾：
   - 更新本任务文档，记录命令、结果和推荐配置。
   - 更新 `doc/requirement-log.md`。
   - 如果新增了汇总脚本或修改训练入口，同步更新 `doc/step_5_training_infra.md`
     和 `doc/scripts_inventory.md`。

## 验收标准

- 至少完成 4 个可比较的 `train-wan` 调参 run。
- 每个 run 都保存 `config.json`、`train_log.jsonl`、`train_summary.json`、
  `best_summary.json` 和至少一个 checkpoint。
- 汇总表包含 baseline 和调参 run，能直接比较 best/final 指标。
- 至少一个调参配置的 `best_eval_loss` 优于 task071 baseline `1145.6176`，或文档明确说明
  未优于 baseline 的原因和下一步建议。
- best checkpoint key 审计通过：无 `human` / `control` key，只保存 trainable-only 权重。
- 任务文档记录最终推荐配置、输出路径、磁盘占用和运行时风险。

结果判断：

- baseline `best_eval_loss=1145.6176`。
- 同一 loss 权重口径下，`r16_lr2e-4_aw1_s1k` 明确优于 baseline：
  `1076.8829` vs `1145.6176`；同时 raw `eval_action_loss` 从 `1145.5135`
  降到 `1076.7936`。
- `action_loss_weight=0.1/0.01` 的 weighted total loss 更低，但因为总 loss 被权重缩放，
  不应直接拿 weighted `best_eval_loss` 与 `aw=1.0` 的 run 做主排名；它们的 raw
  `eval_action_loss` 仍在 `1126.3013` / `1143.7440`。
- 下一轮推荐先把 `r16_lr2e-4_aw1_s1k` 扩展到 `max_steps=3000`；如需偏向 video
  loss，可并行保留 `lr=1e-4, action_loss_weight=0.1` 作为平衡对照。
- `lr=5e-5, action_loss_weight=1.0` 收敛明显慢于 baseline，不建议优先延长。
