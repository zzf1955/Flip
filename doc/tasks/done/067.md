## 背景

当前 FLIP 训练主线仍以 Wan2.2 TI2V-5B / Mitty-style LoRA 为基础，目标是学习
`(synthetic human, real robot)` 配对视频的 robot-to-human 映射。用户后续希望探索
DreamZero 风格的离线 closed-loop video-action world-action model：在没有实机控制闭环的
条件下，用模型预测下一段视频和 action chunk，再把生成视频作为下一轮视觉上下文，离线滚动
生成完整任务。

调研结论：

- DreamZero 主论文 / 官方公开 checkpoint 主要基于 `Wan2.1-I2V-14B-480P`，未看到官方发布的
  Wan2.2-TI2V-5B DreamZero 训练好 checkpoint。
- DreamZero 仓库已经提供 Wan2.2-TI2V-5B backbone 配置和训练脚本，但这是从 Wan2.2-5B 视频
  基座训练 DreamZero-style 模型，不是加载已有 DreamZero-5B policy checkpoint。
- 在 `train_architecture=lora` 下，LoRA 只打在 Wan DiT 主干上；`state_encoder`、
  `action_encoder`、`action_decoder` 是 DreamZero 新增模块，从头初始化并全量训练。
- Wan2.2-5B 路线比 DreamZero-AgiBot / DreamZero-DROID 的 14B 系 checkpoint 更符合当前显存
  约束；用户接受大 rank LoRA 作为全量微调和低显存之间的折中。
- Cosmos Predict2B 有 `Text+Image` / `Text+Video -> Video` 能力，可作为更小 video backbone
  的备选路线，但不能直接替换 DreamZero 的 Wan wrapper；若启用 Cosmos 2B，应走独立
  Cosmos-native action/state latent-slot 或 Cosmos Policy 风格注入。

## 目标

1. 在 FLIP 内建立 Wan2.2-TI2V-5B + DreamZero-style LoRA 的可运行原型任务。
2. 明确 DreamZero action/state register 在本任务中的训练语义：
   - Wan2.2 DiT base weight 冻结；
   - Wan DiT 上训练 LoRA；
   - action/state encoder 和 action decoder 从头全量训练；
   - text encoder、image encoder、VAE 冻结。
3. 将用户已有数据接入 video-action chunk 训练格式，完成最小训练与离线 rollout smoke。
4. 记录 Cosmos Predict2B 路线为备选，不在本任务内实现。

## 范围

- 主线 backbone：`Wan-AI/Wan2.2-TI2V-5B`。
- 参考实现：DreamZero 的 `CausalWanModel`、action/state register、joint video-action diffusion
  训练思路。
- 训练方式：LoRA on Wan DiT + 从头训练 `state_encoder/action_encoder/action_decoder`。
- 任务类型：离线 video-action closed-loop 原型，不接实机控制。
- 本任务不加载官方 DreamZero-AgiBot / DreamZero-DROID 14B checkpoint。
- 本任务不实现 Cosmos Predict2B；仅保留为后续备选方案。
- 不保留隐式 fallback；数据字段、action/state 维度、chunk 对齐、checkpoint schema 不合法时直接失败。

## 实施计划（分步骤）

1. 复核 DreamZero Wan2.2-5B 训练链路，确定需要迁入 FLIP 的最小模块：
   - Wan2.2 DiT / VAE / T5 / CLIP 加载；
   - action/state register 拼接；
   - joint video/action denoising loss；
   - LoRA 注入、保存和恢复。
2. 设计 FLIP 数据适配层：
   - 输入视频分辨率默认采用 Wan2.2-5B 低显存配置 `160x320`；
   - 明确 `num_frames`、`num_frame_per_block`、`action_horizon`、
     `num_action_per_block`、`num_state_per_block`；
   - 明确 action 是 absolute、delta 还是 relative action；
   - 明确 state/proprio 的来源、维度、归一化和滚动更新方式。
3. 新增训练入口或实验脚本：
   - 支持 LoRA rank / alpha / target modules 配置；
   - 支持 action/video loss 权重；
   - 支持短 horizon / 小样本 smoke；
   - 支持保存 LoRA + action/state register 训练参数。
4. 新增离线 rollout 入口：
   - 用初始真实视频或首帧 + text + state 生成下一段 video/action；
   - 将生成视频回填为下一轮 visual context；
   - state 先支持固定 state 或由 action 简化推进；
   - 输出拼接后的 video、action chunk 和每轮中间产物。
5. 完成验证和文档更新：
   - compile / help；
   - checkpoint save/load smoke；
   - 单 batch 训练；
   - 小样本 GPU smoke；
   - 离线 rollout smoke；
   - 记录显存、速度、loss 曲线和失败边界。

## 验收标准

- 能从 Wan2.2-TI2V-5B checkpoint 初始化模型，并确认缺失权重仅限新建 action/state 模块。
- `train_architecture=lora` 下 trainable 参数清单符合预期：
  - Wan DiT LoRA 参数可训练；
  - `state_encoder/action_encoder/action_decoder` 可训练；
  - text encoder、image encoder、VAE 和 Wan DiT base weights 冻结。
- 训练 checkpoint 能完整保存并恢复 LoRA + action/state register 参数。
- 至少完成一个小样本训练 smoke，并记录 `video/dynamics loss` 和 `action loss`。
- 离线 rollout 能输出连续 video chunk 和 action chunk，且生成结果可复现。
- 文档说明主线 Wan2.2-5B + DreamZero 方案、显存取舍、LoRA rank 建议和 Cosmos Predict2B
  备选路线边界。

## 测试要求

- `python -m compileall <新增或修改的 Python 文件>`
- 训练入口 `--help` 或等价参数解析 smoke。
- 单 batch CPU/GPU shape smoke：验证 video latent、action register、state register 和输出切片 shape。
- GPU 小样本训练 smoke：建议从 `lora_rank=16` 开始，再测试 `32/64`。
- checkpoint save/load smoke：恢复后打印 missing / unexpected keys，并跑同一 batch inference。
- 离线 rollout smoke：至少滚动 2 个 chunk，导出 video/action 中间结果。

## 备选路线：Cosmos Predict2B

Cosmos Predict2B 仅作为后续备选，不进入本任务实现范围。选择它的条件是 Wan2.2-5B LoRA
仍无法在当前显存预算下稳定训练，或需要更小的 video backbone 做 video-only / video-action
探索。

备选路线原则：

- 可以复用 DreamZero 的高层思想：视觉条件 + text + action/state 条件，联合预测未来视频和 action。
- 不能直接复用 DreamZero 的 Wan wrapper；Cosmos 的 VAE、DiT、scheduler、token layout 和条件注入方式不同。
- 推荐采用 Cosmos-native latent-slot / latent-frame injection，或参考 Cosmos Policy 的
  proprio/action/future-state latent 注入方式，而不是硬移植 DreamZero action register。
- 第一阶段可先做 `Text+Image/Video -> Video` 的 video-only offline rollout；确认稳定后再加入 action/state。
