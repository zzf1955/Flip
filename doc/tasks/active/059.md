## 背景

现有 [058] Masquerade baseline 已经可以在现有 `h2r` pair 数据上跑通，
但当前实现仍把 robot mesh 当成快速 proxy 来处理，并且 human 侧的擦除链路也还是第一版
骨架。用户这次明确要求把现有“擦除机器人”的代码迁到“擦除人手 / 人腿”上：
先用机器人 mesh 生成粗 prompt，再用 prompt + SAM2 分割 human limbs，
用 ProPainter 重绘背景，最后再把真实的机器人 mesh 渲染贴回去。

这次 task 的目标不是改 action 数据来源，action 仍然直接读原始 segment parquet；
重点是把 human erase 和 robot render 的视觉口径升级到可复现、可比较的版本，
并把当前边界写清楚，避免后续复现口径混淆。

## 目标

1. 将 Masquerade baseline 的 robot 渲染从快速 proxy 升级为真实 Mesh / 高保真 Mesh 渲染。
2. 用机器人 mesh 生成 prompt，驱动 SAM2 分割 human hand / leg 区域，再用 ProPainter 重绘背景。
3. 保持现有 `h2r` pair 输入输出契约不变，仍可直接生成 baseline / compare 产物。
4. 在文档里明确说明当前 pipeline 的真实实现：action 来源、SAM2、ProPainter 和 full-mesh 渲染分别负责什么。

## 范围

- 只处理 `src.pipeline.masquerade_baseline` 里的 robot render 路径。
- 只改 high-fidelity human erase + robot render 的实现与输出口径，不重做整套 `h2r` 数据生产逻辑。
- action 继续来自原始 segment parquet，不从图像中重新提取。
- 不引入隐式 fallback：如果真实 Mesh、SAM2、ProPainter 或渲染后端不可用，应直接失败。
- 保持 compare、summary、manifest 等产物结构稳定，便于和 058 版本直接对照。

## 实施计划（分步骤）

1. 审计当前 proxy 渲染链路，确认 mesh 加载、link 过滤、相机参数、深度排序和遮挡处理的薄弱点。
2. 用机器人 mesh 生成 prompt box，接入 SAM2 做 human hand / leg 分割，替换旧的人体启发式 mask。
3. 接入 ProPainter 做背景重绘，随后用 full mesh 渲染把机器人贴回去。
4. 补充最小 smoke 验证，确保至少一个 task 的少量 pair 能稳定输出高保真 baseline 和 compare 结果。
5. 更新 `doc/step_5_training_infra.md`、`doc/scripts_inventory.md` 和 `doc/requirement-log.md`，把现状、输入依赖和复现注意事项写清楚。

## 验收标准

- 至少能在一个现有 `h2r` task 上跑通高保真 Mesh 渲染 baseline。
- 输出的 baseline 视频、compare 视频和 manifest 结构与现有 baseline 保持兼容。
- 真实 Mesh 渲染在视觉上明显优于当前 proxy 版本，尤其是几何边界、遮挡和轮廓细节。
- 缺少 Mesh、相机、joint、SAM2 或 ProPainter 依赖时直接失败，不做静默回退。
- 文档中明确写出当前实现：robot mesh prompts、SAM2、ProPainter、full-mesh render 和 action 来源各自的职责。

## 测试要求

- 至少对 1 个 task、少量 pair 跑 smoke。
- 检查输出视频帧数、分辨率、compare 排版和 manifest 对齐关系。
- 用现有 058 proxy 结果作对照，确认新版本不是同一条 proxy 渲染路径。
- 如果引入新的依赖或后端，补充最小可复现说明和失败条件。
