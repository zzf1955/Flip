## 背景

现有 Humanoid Everyday H1 训练主要围绕少量子集和单一 pair-IDM 口径展开。当前
`flip/data/humanoid-everyday-h1-chunks0-6-8-200` 数据量更大，且原始数据本身有明确的
task 结构和 `task_index` / task 元信息。为了判断模型到底是在学通用动作条件还是只在
少量样本上记忆，需要把训练扩展到更完整的数据根，并按 task 维度组织实验。

同时，当前主线模型大多还是小 CNN 结构。需要系统探索下游模型是否可以换成
Transformer 类架构，比较 CNN、CNN+Transformer、纯 Transformer 等不同方案在
task 内拟合、跨 task 泛化和训练稳定性上的差异。

## 目标

1. 基于 `flip/data/humanoid-everyday-h1-chunks0-6-8-200` 建立可复用的全量训练与评估流程。
2. 支持按 task / task group / `task_index` 划分训练与验证，避免只靠随机 sample 切分。
3. 构建 task 级训练实验，至少能单独训练某个 task，也能做多 task 联合训练与跨 task 评估。
4. 比较不同模型架构，包括当前小 CNN baseline、加深版 CNN、CNN + Transformer、以及下游
   直接换 Transformer 的方案。
5. 输出统一的实验表，覆盖每个 task 的收敛情况、验证指标、参数量、训练速度和稳定性。

## 范围

- 第一阶段聚焦 Humanoid Everyday H1，不扩展到 WBT 或其他数据源。
- 数据源默认使用 `flip/data/humanoid-everyday-h1-chunks0-6-8-200`，必要时可先做坏 parquet
  过滤或数据索引清理。
- 任务切分需要基于数据集已有 task 元信息，而不是只按 episode 或 sample 随机划分。
- 模型探索包含但不限于：
  - 现有小 CNN baseline
  - 更深的 CNN / 残差 CNN
  - CNN backbone + Transformer head
  - 直接使用 Transformer 作为时序/表征下游
- 训练目标优先沿用当前 H1 pair-IDM 语义，再进一步比较更适合 task 级训练的监督口径。
- 需要同步更新 `doc/step_5_training_infra.md`、`doc/scripts_inventory.md` 和
  `doc/requirement-log.md`。

## 实施计划（分步骤）

1. 梳理 H1 数据里的 task 元信息，明确 task / category / `task_index` 的可用字段和分组口径。
2. 设计 task 级数据切分规则，生成可复用的 train / val / test 或 task holdout 清单。
3. 实现按 task 训练的启动入口或参数，支持单 task、task group 和全量联合训练。
4. 搭建至少 3 类模型架构对照：小 CNN baseline、增强 CNN、Transformer 系列。
5. 统一指标和日志格式，记录每个 task 的 loss、RMSE、baseline、方差比、收敛速度和训练成本。
6. 在若干代表性 task 上先做 smoke，再扩大到更多 task，形成架构对照表。
7. 根据实验结果确定推荐架构和默认任务切分策略，并把结论回写文档。

## 验收标准

- 能够明确按 task 训练和评估，而不是只依赖全局随机 sample 切分。
- 至少完成一轮小规模 task 级实验，对比 CNN 与 Transformer 类架构的差异。
- 实验输出里能看出不同 task 的表现，而不是只给一个混合总指标。
- 文档清楚说明 task 级切分、训练入口和推荐架构。
- 结果中能明确指出哪类架构更适合当前 H1 数据，以及适用条件和局限。

## 测试要求

- 训练入口 `--help` 和 task 切分相关参数可用。
- 至少跑一个单 task smoke，确认训练 loss 和验证 loss 正常。
- 至少跑一个小型多 task 对照实验，确认不同架构都能收敛并输出统一指标。
- 需要有一个可复现的 task split 清单或 manifest。
