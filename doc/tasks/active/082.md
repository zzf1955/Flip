## 背景

用户希望从头使用 human2robot 原始配对数据训练 robot video -> human video
编辑，而不是复用当前 G1 `2s61f30_slide` 反向 cache。当前本地数据有两种来源：

- MP4 视频：`data/h2r/v1/video/<task>/episode_<id>/{robot_camera,human_camera}.mp4`。
  本地共有 210 个 episode，但 `push_box_two_v1/episode_5` 只有 8 帧，无法构造
  61 帧 2s 样本，因此 2s61f30 首窗口口径可用 209 条。
- HDF5 全量：`data/h2r/v1/data/<task>/episode_<id>.hdf5`，内部包含
  `cam_data/robot_camera` 和 `cam_data/human_camera`。本地共有 1312 个 episode，
  其中 `grab_pencil_v1/episode_50.hdf5` 只有 2 帧、`push_box_two_v1/episode_5.hdf5`
  只有 8 帧，因此 2s61f30 首窗口口径可用 1310 条。

新的训练口径要求：

- 2s 数据。
- 30fps。
- 不使用滑动窗口，每个 episode 默认只取一个固定窗口。
- 支持并行处理。

项目既有 2s30fps 约定为 `2s61f30`：使用 61 帧 `0..60`，满足 Wan VAE 的
`4k+1` 输入长度约束；语义上仍表示约 2 秒窗口。

## 目标

1. 新增 human2robot 原始配对到 Mitty 标准 pair layout 的构造入口，用于生成 robot -> human
   的 `r2h` pair。
2. 输出 2s30fps、61 帧、非滑动窗口数据；默认每个 episode 使用首个窗口
   `source_frame_indices=0..60`。
3. 生成 pair 目录后，用现有 `src.pipeline.mitty_cache` 构造 VAE/T5 cache。
4. pair 生成阶段支持多线程并行；cache 阶段支持按 task/GPU 并行启动多个
   `mitty_cache` 进程。
5. 明确区分这批 human2robot 原始数据和当前 G1 `2s61f30` / `2s61f30_slide` 数据，禁止覆盖
   已有 G1 pair/cache。

## 范围

- 新增 pipeline 入口，建议命名为 `src.pipeline.human2robot_r2h_pair`。
- 新增 `scripts/flip_run.sh` 子命令，建议命名为 `human2robot_r2h_pair`。
- 说明：当前 `.worktrees/t082` 的历史实现入口仍叫 `h2r_r2h_pair`；合入前应按
  human2robot 命名规则改名，避免与 `data_type=h2r` 混淆。
- 默认输出：

```text
training_data/pair/r2h/2s61f30_human2robot_v1/<task>/
  video/pair_0000.mp4
  control_video/pair_0000.mp4
  metadata.csv
  manifest.jsonl
training_data/pair/r2h/2s61f30_human2robot_v1/index.jsonl
```

- `control_video` 为 robot input，`video` 为 human target：

```text
control_video/pair_NNNN.mp4 = robot_camera clip
video/pair_NNNN.mp4         = human_camera clip
data_type                   = r2h
input_role                  = robot
target_role                 = human
```

- 默认读取 MP4 视频源；保留参数化空间支持 HDF5 全量源，但首轮实现必须至少跑通
  MP4 源。
- 默认输出尺寸使用 `224x416`（HxW），与现有 human2robot SAM3 blur_r2r 数据一致，避免原始
  `240x426` 产生不适合 Wan/Mitty 训练的 latent grid。
- 不实现滑动窗口；不做水平翻转增强；不隐式 fallback 到 1s/16fps 或已有 G1 cache。
- 不自动启动正式训练。

## 实施计划（分步骤）

1. 实现 human2robot 配对发现：
   - 扫描 `data/h2r/v1/video` 下的 episode。
   - 校验 `human_camera.mp4` 与 `robot_camera.mp4` 同时存在。
   - 校验两侧 fps 均为 30，尺寸和帧数一致；不一致直接失败。
   - 跳过或显式报出少于 61 帧的 episode；默认建议 `--skip-short` 跳过并写入 summary。
2. 实现非滑窗 2s clip 构造：
   - 默认 `start_frame=0`。
   - `source_frame_indices=list(range(0, 61))`。
   - 读取两侧相同帧索引。
   - resize 到 `224x416`。
   - 按 30fps 写出 61 帧 mp4。
3. 实现并行 pair 写出：
   - CLI 参数 `--workers` 控制 `ThreadPoolExecutor`。
   - 每个 task 内按 `source_id` 稳定排序并编号 `pair_0000`。
   - `--resume` 跳过已完整写出的 pair；`--clean` 只清理目标 duration 下对应 task，
     不能删除项目外路径或其它 duration。
4. 写出标准 metadata / manifest：
   - `metadata.csv` 字段保持 `video,prompt,control_video`。
   - `manifest.jsonl` 至少包含 `data_type`、`duration`、`robot_task`、`task`、
     `episode`、`clip_idx`、`clip_start_frame`、`source_frame_indices`、
     `source_id`、`source_segment_id`、`human_src`、`robot_src`、`resize`、`fps`、
     `num_frames`、`input_role`、`target_role`、`video`、`control_video`、`pair_id`。
   - 写出全局 `index.jsonl` 和 summary JSON，记录可用、跳过、失败数量。
5. 接入 cache 构造：
   - 复用 `scripts/flip_run.sh mitty_cache`。
   - 显式传 `--t5-cache-dir training_data/cache/t5/r2h/2s61f30_human2robot_v1`，不要依赖
     `mitty_cache` 对 duration 目录的自动推断。
   - VAE 输出到 `training_data/cache/vae/r2h/2s61f30_human2robot_v1/<task>`。
   - 提供按 GPU/task 并行运行的命令或小 launcher；每个进程独立处理一个 task 目录。
6. 更新文档：
   - 更新 `doc/pipeline/training_infra.md`，记录 human2robot r2h 2s61f30 数据 layout、
     字段语义、生成命令和 cache 命令。
   - 更新 `doc/requirement-log.md`。

## 验收标准

- dry-run 能输出任务级 episode 数、短 episode 数和预计 pair 数。
- MP4 源正式 pair 生成后，`training_data/pair/r2h/2s61f30_human2robot_v1/index.jsonl`
  应有 209 条，且记录 `push_box_two_v1/episode_5` 被跳过。
- 抽样 pair 视频满足：
  - `video/*.mp4` 为 human target。
  - `control_video/*.mp4` 为 robot input。
  - 30fps。
  - 61 帧。
  - 分辨率 416x224（OpenCV/ffprobe 宽 x 高）。
- `manifest.jsonl` 与 `metadata.csv` 行数一致，`pair_id` 无重复。
- 至少对一个 task 跑通 `mitty_cache` smoke，并生成 `manifest.jsonl`。
- 全量 cache 生成后，cache manifest 行数与对应 pair manifest 行数一致。
- `src.pipeline.train` 使用 `--data-type r2h --duration 2s61f30_human2robot_v1` 做 runtime split
  时能通过 pair/cache 一致性校验。
