## 背景

human2robot R2H 2s forward 数据已经离线划分为 train/test/eval，其中 test split
包含 ID 和 OOD 样本。现有 `evaluate_mitty_models` 离线评估入口主要服务
`in_task_eval` / `ood_eval`，不能直接按新数据集的 `test.jsonl` 采样 ID/OOD
各 500 条并输出到统一 `training_data/eval/` 目录。

## 目标

- 支持对 human2robot R2H 显式 test split 做离线评估。
- test 评估从 `test.jsonl` 中按 `domain=id/ood` 分别采样，默认 ID 500 条、
  OOD 500 条。
- 生成一个可 dry-run 的测试评估脚本，输出视频和 summary 到 `training_data/eval/`。

## 范围

- 扩展离线 eval split 构建逻辑，使 `test_id` / `test_ood` 可作为评估 split。
- 新增脚本封装 rank512 或指定 run 的最新 checkpoint test 评估命令。
- dry-run 只打印命令和计划，不启动视频生成或指标计算。
- 不修改训练逻辑，不重新切分数据，不改动已有训练 run 内容。

## 实施计划（分步骤）

1. 检查现有 `evaluate_mitty_models`、`eval_mitty/run_specs.py` 和 split 数据结构。
2. 在 runtime/eval split helper 中支持显式 test split 的 ID/OOD 子集采样。
3. 新增 `scripts/eval_human2robot_r2h_test.py`，支持 `--dry-run`、`--sample-per-domain`、
   `--runs`、`--checkpoint latest`、`--cuda-list`、`--output-root`。
4. dry-run 输出每个 run 的 checkpoint、样本数、输出目录和实际 `flip_run.sh eval_mitty`
   命令。
5. 更新相关文档和 requirement log。

## 验收标准

- dry-run 能列出 3 个 rank512 run 的评估命令。
- 每个 run 计划采样 `test_id=500`、`test_ood=500`。
- 输出根目录为 `training_data/eval/<eval_name>/`。
- 不启动真实评估进程。

## 测试要求

- Python 编译检查覆盖新增/修改的脚本与模块。
- 针对 split 采样逻辑增加单元测试或最小本地构造测试。
- 执行新脚本 dry-run，确认命令和输出目录正确。
